Curl_json

for i in $(cat test); do
  out=$(curl -s -G 'http://help.htb:3000/graphql' --data-urlencode "query={ user { $i } }")
  if ! echo "$out" | jq -e 'has("errors")' >/dev/null 2>&1; then
    echo "$i: " $(echo "$out" | jq -r '.data.user // ""')
  fi
done

Explain

  • out=$(curl -s -G 'http://help.htb:3000/graphql' --data-urlencode "query={ user { $i } }") — perform an HTTP GET to the GraphQL endpoint.
    • -s silences curl progress output.
    • -G makes curl send data as query-string parameters (instead of POST body).
    • --data-urlencode URL-encodes the provided value so special chars (spaces, braces, quotes) are safe in the URL.
    • The GraphQL query string is built inline as { user { <field> } } where $i is substituted by the shell.
    • Result (JSON) is stored in the shell variable out.
  • if ! echo "$out" | jq -e 'has("errors")' >/dev/null 2>&1; then — test whether the JSON response **does not** contain an errors key:
    • echo "$out" | jq -e 'has("errors")' returns success (exit code 0) when the JSON has an errors key; the ! negates that test.
    • Redirecting output to /dev/null hides jq’s stdout/stderr; the script uses jq’s exit code only.
  • echo "$i: " $(echo "$out" | jq -r '.data.user // ""') — print the field name ($i) and the value returned by GraphQL:
    • jq -r '.data.user // ""' extracts data.user (raw string, no quotes). If data.user is missing/null, the // "" fallback yields an empty string.
  • done — end loop.
