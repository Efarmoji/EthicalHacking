Git Repo CVE-2022-24439

GitPython is a Python library that lets you interact with Git repositories using Python code instead of Git CLI commands.

Mechanism

1. GitPython provides a wrapper for Git's clone functionality via Repo.clone_from(), which internally uses the Git CLI.

2. When you pass a URL string, it's inserted directly into a shell command without sanitization.

3. If that string starts with the special prefix ext::, Git interprets it using the "ext" transport protocol, invoking the shell.

ext::sh -c "touch /tmp/pwned"

So, common usage is:

git clone https://some-git-url/

But this arg[1] can receive something like:

git clone ext::sh -c 'echo HELLO' myrepo

What is ext::

ext:: is a special URL scheme used by Git to invoke a custom transport helper via the shell.

Instead of using http:// or https://, it uses an external shell command to handle the Git operation.

Git supports custom protocols through transport helpers, so you can write your own tools to clone/push/fetch over non-standard protocols (like FTP, custom APIs, etc.).

In short, git clone ext:: ... means "please clone this custom protocol to somewhere".

Deeper

Common usage git clone https://github.com/user/repo.git can be explained like this:

git clone <protocol>://<host>/<repo>.git

Git parses:

https = protocol

github.com/user/repo.git = path to the repo

Now with ext::

git clone ext::sh -c 'bash /tmp/shell.sh' newrepo

This time:

1. ext:: tells Git to call an external command.

2. Git replaces the ext:: with a literal shell call.

3. Git runs sh -c 'bash /tmp/shell.sh' as a transport helper.

Git doesn't care that this doesn't point to a .git repo — because it assumes you are implementing the protocol using your custom command.
