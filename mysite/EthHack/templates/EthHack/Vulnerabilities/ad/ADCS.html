Certificate Mapping

Certificate mapping is how AD figures out which user a certificate belongs to, usually by checking fields like the UPN, SAN, or objectSid in the certificate. If we can trick AD into thinking a cert belongs to a different user, like a Domain Admin, we can log in as that user.

Jargons

UPN

- UPN stands for User Principal Name, which is the primary logon name for a user account in systems like Microsoft Active Directory and Microsoft Entra ID.

SAN

- Refers to Subject Alternative Name, a field in digital certificates used to secure multiple hostnames or IP addresses with a single SSL/TLS certificate. This is useful for services like Active Directory Certificate Services (AD CS) to issue certificates for different server names or IP addresses under one certificate, simplifying configuration.

objectSID

- A binary attribute in Microsoft Active Directory that contains the unique Security Identifier (SID) for a security principal like a user, group, or computer.

StrongCertificateBindingEnforcement

- Verifies certificate ownership during authentication.

- Controls how strict the certificate validation is, with three modes

  • Disabled Mode (0) : No strong checks are performed.
  • Compatibility Mode (1) : The DC first looks for the objectSid in the certificate. If it's missing, the DC may still allow login if the user account existed before the cert was issued.
  • Full Enforcement Mode (2): : The DC only allows login if the certificate contains a valid objectSid. If it's missing, login is denied.
