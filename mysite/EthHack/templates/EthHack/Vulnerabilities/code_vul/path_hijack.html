What is $PATH-HIJACK?

  • Definition: A PATH hijack happens when a malicious executable is placed in a directory that appears earlier in a user's $PATH, causing an unqualified command name to run the attacker's binary instead of the intended one.
  • Why it's dangerous: Privileged scripts or interactive shells that call programs by name (not absolute path) can execute arbitrary code, leading to privilege escalation.
  • Detect: Inspect echo $PATH for writable or unusual directories; run ls -ld <each_path> to check permissions and ownership. Search for unexpected executables (e.g., find /tmp /dev/shm $HOME -type f -executable -name 'sudo*' 2>/dev/null).
  • Mitigate:
    • Remove writable directories from privileged users' $PATH.
    • Use absolute paths in scripts (e.g., /usr/bin/openssl instead of openssl).
    • Fix directory permissions/ownership so only trusted users can write.
    • Enforce a secure path (e.g., Defaults secure_path="/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin" in /etc/sudoers).
    • Monitor changes to ~/.ssh, /tmp, and other writable locations for new executables.
