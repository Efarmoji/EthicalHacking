What is XEE (aka XXE)?

XEE/XXE (XML External Entity) is a class of XML parser misconfigurations where user-supplied XML can reference external resources (files/URLs). If a parser resolves those references, it can disclose sensitive data or make unintended network requests.

  • Root cause: XML parser allows <!DOCTYPE … > with external entities (e.g. SYSTEM/PUBLIC).
  • Impact: file disclosure, SSRF, error-based leaks; in rare cases, DoS via large entity expansion.
  • Fix: disable DTDs & external entity resolution by default; validate strictly; prefer safer data formats.

Core Concepts

TermMeaning
DTD Document Type Definition; can declare entities. Dangerous when enabled for untrusted XML.
External Entity Entity whose value comes from an external resource (SYSTEM "file:///…" or URL).
Parameter Entity DTD-scoped entity (starts with %); also risky if processed.
XXE Exploitation of a parser that resolves external entities.

The Flow (at a glance)

Parser accepts DTD → External entity resolves → Sensitive data/requests leak

  • Application receives XML from client
  • Parser processes <!DOCTYPE> and resolves SYSTEM/PUBLIC entity
  • Entity value is inserted into XML tree → may disclose file content or trigger outbound request

Safe Demo Payloads (for authorized test envs)

1) Minimal XML with external entity

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE note [
  <!ENTITY test SYSTEM "file:///path/to/a/harmless/test.txt">
]>
<note>&test;</note>

2) POST an XML body (common)

kali@kali:~ $ curl https://target.example.com/api/xml \
  -H "Content-Type: application/xml" \
  --data-binary @payload.xml

3) GET with XML param (less common)

kali@kali:~ $ curl -G "https://target.example.com/api" \
  --data-urlencode 'xml=<?xml version="1.0"?><root/>'

Important: Only test on systems you own or have explicit permission to assess. Use innocuous file paths in labs (e.g., a benign test file you create).

Reading Responses

  • If the entity is resolved, its value may appear in the normal response or in error messages.
  • Some apps normalize or strip XML; watch server logs and error traces during testing (authorized only).

Mitigation (High-Level)

PlatformWhat to disableNotes
General XML parsers Disallow DTDs; disable external entity resolution (both general & parameter entities) Reject any input containing <!DOCTYPE> unless absolutely required
App logic Use strict schemas; prefer JSON where possible Whitelist expected fields; reject unexpected nodes
Network Block outbound egress from app containers Prevents SSRF-style XXE impact
Secrets handling Never store secrets in web-readable paths Use vaults; least-privilege FS permissions

Detection Tips

  • Endpoints that accept XML (Content-Type: application/xml or text/xml)
  • Error messages mentioning DTD, DOCTYPE, entities, or parser features
  • Unexpected outbound DNS/HTTP requests from the app (in controlled tests)

Quick Reference

Safety

  • Use dedicated lab targets or explicit scopes; log consent.
  • Prefer benign test files and non-network entities during basic checks.
  • If you find a real issue, follow responsible disclosure guidelines.

4) Detect XML format/type from a URL

kali@kali:~ $ curl -s https://0xdf.gitlab.io/feed.xml | xmllint --format - | head -16

What this does

  • curl -s quietly downloads the XML.
  • xmllint --format - pretty-prints from STDIN (and errors if not well-formed).
  • head -16 shows the XML declaration and the root element so you can identify the type.

What to look for in the first lines

<?xml version="1.0" encoding="UTF-8"?>
<feed xmlns="http://www.w3.org/2005/Atom">          ← Atom feed
# or:
<rss version="2.0">                                  ← RSS 2.0
# or:
<rdf:RDF xmlns="http://purl.org/rss/1.0/">          ← RSS 1.0 (RDF)
# or:
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">  ← XML Sitemap
# or:
<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">  ← SOAP

Optional: get only the root element name

kali@kali:~ $ curl -s https://0xdf.gitlab.io/feed.xml | xmllint --xpath 'name(/*)' -; echo
feed

Troubleshooting

  • If you see “parser error”, the response may not be XML (check with curl -I <URL> for Content-Type).
  • Compressed content? Try curl -s --compressed <URL>.
  • Redirects? Add -L to curl.
