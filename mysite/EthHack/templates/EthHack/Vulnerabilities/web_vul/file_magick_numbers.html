What are File Magic Numbers?

File magic numbers are fixed byte sequences located at (or near) the start of a file that uniquely identify its format (for example PNG: 89 50 4E 47 0D 0A 1A 0A). They are more reliable than filename extensions and are used by tools like file, parsers, and antivirus to determine file type.

Why magic numbers matter

  • Verify true file type when extensions are misleading or changed.
  • Detect maliciously renamed files (e.g., executables with .jpg extension).
  • Useful in forensics, malware analysis, and automated triage.

Quick detection tools

  • file — uses a magic database to identify file types.
  • xxd / hexdump — view raw header bytes in hex for manual inspection.
  • binwalk — scan for embedded files and signatures (good for firmware/binaries).

Real Case

echo '89 50 4E 47 0D 0A 1A 0A' | xxd -p -r >> hex_rev.php.png

  • echo '89 50 4E 47 0D 0A 1A 0A' — prints the hex string followed by a newline. Whitespace is OK; xxd treats spaces/newlines as separators.
  • | — pipes that printed text into the next command.
  • xxd -p -r — xxd -p expects a plain (continuous or space-separated) hex stream; -r reverses the dump (hex → binary). The hex becomes the 8 raw bytes: 0x89 0x50 0x4E 0x47 0x0D 0x0A 0x1A 0x0A.
  • > hex_rev.php.png — appends the resulting binary bytes to the file hex_rev.php.png. If the file doesn't exist it will be created; if it exists the bytes are appended (not overwritten).
  • Notes:
    • Those bytes are the PNG signature (\x89PNG\r\n\x1A\n). Appending them to a file does not make a valid PNG unless the rest of the PNG structure exists.
    • To create/overwrite a file starting with the signature, use > (overwrite) and printf for cleaner output, e.g.: 
      printf '89504E470D0A1A0A' | xxd -p -r > new.png
    • Verify what you wrote with commands like: 
      xxd -l 8 hex_rev.php.png
            hexdump -C -n 8 hex_rev.php.png
            file hex_rev.php.png
    • Be cautious: filenames like something.php.png can be used to bypass naive upload filters.

How to check a file's magic (copy-paste)

  • Use file (first check): 
    file suspicious.bin
  • View raw header (hex): 
    xxd -l 32 suspicious.bin
# or
hexdump -C -n 32 suspicious.bin
  • Compare to known magic: 
    # print the first bytes as hex for quick comparison
head -c 16 suspicious.bin | xxd -p -c 16
  • Scan embedded signatures: 
    binwalk suspicious.bin

Example — verify a PNG

xxd -l 8 image.png
# output:
00000000: 8950 4e47 0d0a 1a0a  .PNG....

Why extensions can be misleading

  • Attackers often rename executables as images or documents to bypass naive filtering.
  • Forensic/triage tools should rely on magic numbers, not filenames.
  • When automating checks, validate both the extension and the magic; flag mismatches for review.

Limitations & gotchas

  • Some formats embed multiple signatures (containers like ZIP); check deeper if needed.
  • Files can be crafted to mimic magic bytes (spoofing); combine analysis (entropy, file structure, parsers).
  • Text-based formats (CSV, JSON) often lack strong magic numbers — rely on content heuristics.

Quick workflow (for analysts)

  • 1. Run file to get a first guess.
  • 2. Inspect first 32 bytes with xxd or hexdump.
  • 3. Use binwalk or a dedicated parser if archive/firmware suspected.
  • 4. If mismatch between extension and magic, quarantine and analyze further.

Useful one-line commands

  • file -k suspicious.* — keep going after first match (show multiple matches).
  • xxd -l 16 file | awk '{print $2 $3 $4}' — raw first-16-bytes hex (quick fingerprint).
  • head -c 512 file | strings | head — peek for readable headers/metadata.

Short security note

  • Always validate uploaded files by magic number and content parsing (not just extension) when accepting user files.
  • Reject or sandbox files with mismatched extension vs magic, especially in web upload contexts.
