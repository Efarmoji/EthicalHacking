HTB Retro

Steps

1. Enumeration with nmap.

2. Enumerate smb details with nxc.

3. Brute fource vulnerable account with nxc.

4. Find an AD account and exploit the vulnerability with smbclient, impacket-changepasswd, and crackmapexec.

5. Connect to the target machine with evil-winrm.

nmap - nxc - smbclient - impacket-changepasswd - crackmapexcec - certipy-ad - evil-winrm

There are important information.

  • BANKING$ is an AD machine (computer) account. The trailing $ indicates it's a machine account.
  • If the account was pre-created as a “pre-Windows 2000 computer”, its initial password is the account name in lowercase. → So for BANKING$, the password would be banking.
  • If the machine hasn't joined/authenticated to the domain yet (the secure channel isn't established), its password can be changed.

Therefore, first verify whether BANKING$ / banking works.

└─$ smbclient //retro.vl/Notes -U 'BANKING$%banking'
session setup failed: NT_STATUS_NOLOGON_WORKSTATION_TRUST_ACCOUNT

As we thought, it returned NT_STATUS_NOLOGON_WORKSTATION_TRUST_ACCOUNT.

  [!] Vulnerabilities
      ESC1                              : 'RETRO.VL\\Domain Computers' can enroll, enrollee supplies subject and template allows client authentication

Perfect.

  • From the Certipy results, the CA retro-DC-CA is vulnerable to ESC1—meaning a certificate can be requested for another username via a permissive template. That certificate can be used for logon, so you can impersonate another user (e.g., Administrator) to authenticate to the domain.
  • The Enrollment Rights include Domain Computers, and BANKING$ is a member. Therefore, with BANKING$ credentials you're allowed to enroll against the vulnerable template.
  • You note the CA Name, Template Name, and Minimum RSA Key Length from Certipy because they're effectively the destination, form name, and formatting requirements your CSR must satisfy. In this case, you use the RetroClients template and set the subject to Administrator to request a certificate.
  • Once you obtain that certificate, you can authenticate to the domain without a password (e.g., via PKINIT to get a TGT), which can lead to privilege escalation.

Let's make use of the info!

└─$ certipy-ad req -u 'banking$' -p 'ezpawn!' -dc-ip 10.129.234.44 -ca retro-DC-CA -template RetroClients -upn Administrator -debug -target dc.retro.vl -key-size 4096 -sid S-1-5-21-2983547755-698260136-4283918172-500
