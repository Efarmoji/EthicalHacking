Foothold

Because we got credential from FTP server, we might be able to log on to the HTTP. However, when I tried to login, it returned error message.

Considering the build date of this machine, 2019, the password PrTg@dmin2018 is out of date, and the user owner may be reluctant to change password entirely. So, we may use password with just changing year part.

As expected, I could pass the login form with credential prtgadmin: PrTg@dmin2019. Seeing the installed version section, 18.1.37.13946 is the running version on this website.

Searching a keyworn 'PRTG < 18.2.39 poc' revealed RCE vulerability. Also, this page explains the steps for exploitation. According to the article, we can cause RCE with notification function.

Aheading to notification with setup section on top right -> account setting -> notification, you can see add button for new notification.

Leaving first section default and skip to the Execute Program, and add parameter below...

abc.txt ; net user xef0 asedf123! /add ; net localgroup administrators xef0 /add

Then, re-navigate to the notification page and press bell mark. This might cause RCE and create administrator user named xef0.

※ Because of Windows password policy, your password cannot contain the user's account name or full name. Don't set password like 'user: user123asdf'

If the RCE occured successfully, we can logon to target machine with impacket-psexec.
