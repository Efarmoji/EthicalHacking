Then we can analyze target's objects structure to find the path to the Domain Admins.

Analysis with BloodHound

\

First of all, I found the user svc-alfresco is the member of the group Account Operators.

According to the Microsoft official documents...

The Account Operators group grants limited account creation privileges to a user. Members of this group can create and modify most types of accounts, including accounts for users, Local groups, and Global groups. Group members can sign in locally to domain controllers.

This means, if there is a group which is highly privileged, we can add arbidtary users to the group and obtain the privileges.

Also, searching the pathway to the Domain Admins, I found there is a group EXCHANGE WINDOWS PERMISSION which has WriteDacl privilege to the target machine. We can create user and make it into this higly privileged group, and take full access to the group.

Microsoft official documets :

If an object has a DACL, the system allows only the access that is explicitly allowed by the access control entries (ACEs) in the DACL.

Let's create user who is member of the group exchange windows permission.

*Evil-WinRM* PS C:\Users\svc-alfresco\desktop> net user me test123! /add /domain
The command completed successfully.

*Evil-WinRM* PS C:\Users\svc-alfresco\desktop> net group "Exchange Windows Permissions" me /add
The command completed successfully.

*Evil-WinRM* PS C:\Users\svc-alfresco\desktop> net localgroup "Remote Management users" me /add
The command completed successfully.

Then, we can add DCsync right to the user me we created. We can do that with PowerView.

*Evil-WinRM* PS C:\Users\svc-alfresco\desktop> upload ../utils/Windows/PowerView.ps1
