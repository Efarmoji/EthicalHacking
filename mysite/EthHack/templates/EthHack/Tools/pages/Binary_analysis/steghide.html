What is steghide?

steghide is a steganography tool that hides and extracts data inside media files (cover files). Supported formats include JPEG, BMP, WAV, and AU (not PNG). Data is optionally compressed and encrypted with a passphrase.

Quick Start

Embed (hide) a file

kali@kali:~ $ steghide embed -cf cover.jpg -ef secret.txt -sf stego.jpg
# -cf: cover file to hide in
# -ef: file to embed
# -sf: output stego file (avoid overwriting the original)
# will prompt for a passphrase (use -p to pass non-interactively)

Extract (reveal) hidden data

kali@kali:~ $ steghide extract -sf stego.jpg -xf recovered.txt
# -sf: stego file (with hidden data)
# -xf: output path for extracted data
# will prompt for the same passphrase used during embedding

Inspect a file

kali@kali:~ $ steghide info cover_or_stego.jpg
# Add -p to test with a passphrase and reveal more details if present:
kali@kali:~ $ steghide info stego.jpg -p 'your-passphrase'

Useful Flags

Flag What it does Example
-cf <file> Cover file (carrier media) -cf cover.jpg
-ef <file> File to embed -ef secret.txt
-sf <file> Output stego file (embed) or input stego file (extract) -sf stego.jpg
-xf <file> Path to write extracted data -xf recovered.bin
-p <pass> Passphrase (non-interactive) -p 'S3cure!'
-z <level> Compression level (0–9) -z 9
-e <algo> Encryption algorithm (e.g., aes-256-cbc) -e aes-256-cbc
-f Force overwrite (be careful) -f
info Show whether data might be embedded (more reveals with the right -p) steghide info file.jpg

Common Workflows

Strongly protected embed

kali@kali:~ $ steghide embed -cf photo.jpg -ef creds.tar.gz -sf trip.jpg -z 9 -e aes-256-cbc
# prompts for passphrase; uses max compression and strong encryption

Batch hunting for hidden data

kali@kali:~ $ find . -type f -iname '*.jpg' -exec steghide info {} \; | grep -B1 -i 'embedded data'

Automated extract with known passphrase

kali@kali:~ $ steghide extract -sf stego.jpg -xf loot.bin -p 'hunter2'

Tips & Notes

  • Formats: works with JPEG/BMP/WAV/AU (not PNG). Re-encoding or resizing the cover can destroy hidden data.
  • OPSEC: choose a strong passphrase; prefer compressing the payload first (.tar.gz), then embed.
  • Detection: statistical stego analysis or recompression often breaks/flags embeds—don’t rely on it for robust secrecy.
  • Cracking: If you suspect steghide was used and only have the stego file, tools like stegseek can attempt passphrase guessing.

Real Case

Extract with a known passphrase

kali@kali:~ $ steghide extract -p 'UPupDOWNdownLRlrBAbaSSss' -sf irked.jpg
  • extract: tells steghide to pull hidden data out of the cover file.
  • -p 'UPupDOWNdownLRlrBAbaSSss': the passphrase used when the data was embedded. Quotes keep special characters safe from the shell.
  • -sf irked.jpg: the stego (cover) file that supposedly contains hidden data.
  • Output location/name: If no -xf is given, steghide writes the extracted file using the original embedded filename into the current directory (you’ll see a message like “wrote extracted data to secret.txt”). Use -xf <path> to choose the output name/path.

Verify / Troubleshoot

kali@kali:~ $ steghide info irked.jpg -p 'UPupDOWNdownLRlrBAbaSSss'   # confirm data is present
# If you see “could not extract any data with that passphrase”:
#  - Passphrase is wrong, or
#  - File wasn't made with steghide / no data embedded.
