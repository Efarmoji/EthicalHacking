What is snmpwalk?

snmpwalk queries an SNMP agent to retrieve MIB data—system info, interfaces, routing tables, and configuration. Use it to enumerate network devices, check for default or weak community strings, discover exposed sensitive values, and map device capabilities during network or IoT recon.

Useful MIB OIDs (hrSWRun / host resources & TCP)

Quick reference table of OIDs you commonly query with snmpwalk when enumerating running processes, installed software, users and local TCP ports on a host that exposes SNMP.

OID Description
1.3.6.1.2.1.25.1.6.0 System Processes (host resources: number of processes / basic process info)
1.3.6.1.2.1.25.4.2.1.2 Running Programs (hrSWRunName) — names of running processes
1.3.6.1.2.1.25.4.2.1.4 Process Path (hrSWRunPath) — filesystem path for processes where available
1.3.6.1.2.1.25.2.3.1.4 Storage Units (hrStorageAllocationUnits / hrStorageSize entries) — identifies storage blocks and sizes
1.3.6.1.2.1.25.6.3.1.2 Software Name (hrSWInstalledName) — installed software package names (host software table)
1.3.6.1.4.1.77.1.2.25 User Accounts (MS-USER-MIB / local user list on Windows hosts that expose this enterprise OID)
1.3.6.1.2.1.6.13.1.3 TCP Local Ports (TCP-MIB: local port entries for sockets)

Command explanation

snmpwalk -c public -v1 192.168.50.151 1.3.6.1.4.1.77.1.2.25

What this command does

  1. -c public: uses the SNMP community string public. This is the "password" for SNMP v1/v2c read-only access.
  2. -v1: uses SNMP version 1. (If the target uses SNMP v2c or v3, change accordingly.)
  3. 192.168.50.151: the IP address of the target device you are querying.
  4. 1.3.6.1.4.1.77.1.2.25: the starting OID to walk — in this case the enterprise OID for user accounts (Microsoft user table). snmpwalk will walk that subtree and print each returned variable.

Expected output

You should see SNMP variable lines like:

SNMPv2-SMI::enterprises.77.1.2.25.1.2.1 = STRING: "Administrator"
SNMPv2-SMI::enterprises.77.1.2.25.1.2.2 = STRING: "Guest"
...

Practical notes & troubleshooting

  • If snmpwalk returns Timeout or No Such Object, try a different SNMP version (-v2c) or verify the community string.
  • Many devices disable SNMP by default or use a non-public community string — check configuration or use a discovery tool (e.g., snmp-check or onesixtyone).
  • For Windows hosts, extra SNMP extensions (enterprise MIBs) may be required to expose user lists — not all hosts provide 1.3.6.1.4.1.77.1.2.25.
  • SNMPv3 is preferable in production (auth/privacy). When using SNMPv3, use snmpwalk -v3 -u <user> -l authPriv -A <auth-pass> -X <priv-pass> ....

Security note: the public community string is read-only and widely known; many devices still use it — treat SNMP data as sensitive (it may reveal running services, users and open ports).

Real Case

snmpwalk -v 1 -c public 10.10.11.136

  • Runs an SNMP walk using SNMPv1 with community string public against 10.10.11.136.
  • Uses GET/GETNEXT to retrieve MIB objects (sysDescr, interfaces, routing).
  • Slower and less feature-rich than v2c (no GETBULK), but compatible with legacy devices.
  • Community strings are plaintext—SNMPv1 is insecure; prefer SNMPv3 for authentication/encryption.
  • Try -v2c first for speed; fall back to -v1 if the device rejects v2c.

snmpwalk -v 2c -c public 10.10.11.136

  • Runs an SNMP walk using SNMPv2c with community string public against 10.10.11.136.
  • Uses GETBULK (when supported) for faster retrieval of large MIB tables.
  • Enumerates interfaces, counters, system info, routing and other MIB objects.
  • Community strings are plaintext in v2c—SNMPv3 is required for authentication/encryption.
  • Try -v2c first for speed; fallback to -v1 if the agent rejects v2c.
