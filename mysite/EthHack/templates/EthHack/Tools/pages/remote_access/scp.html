What is scp?

scp securely copies files between hosts over SSH. It uses your SSH keys/options and supports uploading, downloading, and recursive directory transfers.

Quick start

Download from remote

kali@kali:~ $ scp user@host:/path/remote.bin ./remote.bin

Upload to remote

kali@kali:~ $ scp ./local.bin user@host:/path/

Copy directories

kali@kali:~ $ scp -r ./site user@host:/var/www/site

Common recipes

Copy with a specific port and key

kali@kali:~ $ scp -P 2222 -i ~/.ssh/lab_key notes.txt lab@10.10.10.10:/home/lab/

Preserve timestamps/permissions

kali@kali:~ $ scp -rp ./config lab@host:/etc/app/

Copy between two remotes (through you)

kali@kali:~ $ scp -3 user1@hostA:/tmp/dump.sql user2@hostB:/var/backups/

When you need resume/integrity

scp doesn’t resume partial transfers. For large files, prefer: 

kali@kali:~ $ rsync -avzP -e ssh big.iso user@host:/path/

Real case

kali@kali:~ $ scp -v -o MACs=hmac-sha2-256 -i id_rsa djmardov@10.129.69.182:/usr/bin/viewuser viewuser
  • scp: secure copy over SSH.
  • -v: verbose SSH logging (handshake/algorithms/hostkey) — useful for debugging auth/ciphers.
  • -o MACs=hmac-sha2-256: pass an SSH client option that forces the message-authentication code (integrity check) to hmac-sha2-256. Handy when the server only allows certain MACs or you want to avoid weak ones.
  • -i id_rsa: use the given private key for authentication (ensure chmod 600 id_rsa).
  • djmardov@10.129.69.182:/usr/bin/viewuser: remote source — user, host, and absolute path to copy from.
  • viewuser: local destination filename (will write into current directory).

Notes & troubleshooting

  • If the SSH port isn’t 22: add -P <port>.
  • If remote file needs root to read, scp won’t escalate. Workaround: 
    kali@kali:~ $ ssh -i id_rsa djmardov@10.129.69.182 'sudo cat /usr/bin/viewuser' > viewuser
  • Host key prompts: first connection will ask to trust the host. Automate with known_hosts or -o StrictHostKeyChecking=accept-new.
