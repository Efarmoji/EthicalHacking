What is OpenSSL?

OpenSSL is a widely used cryptography toolkit and TLS/SSL library. The command-line tools let you generate/manage keys, create certificate signing requests (CSR), inspect/convert certificate formats, and test TLS services.

  • Works with RSA/ECDSA/Ed25519 keys and PEM/DER/PKCS#12 formats
  • Creates CSRs and self-signed certificates for testing
  • Debugs TLS endpoints (s_client) and inspects certificates

Core Concepts

TermMeaning
Private keySecret material (e.g., RSA/ECDSA) used to sign/decrypt. Must be protected.
Public keyDerived from the private key; shared to verify signatures/encrypt to you.
CertificatePublic key + identity info, signed by a CA (or self-signed).
CSRCertificate Signing Request—what you send to a CA to obtain a cert.
PEM / DER / P12Encodings: PEM (Base64 + headers), DER (binary), PKCS#12/PFX (bundle with key+cert).

Usage

Extract .pem and .key inside of .pfx file.

openssl pkcs12 -in legacyy_dev_auth.pfx -nocerts -out key.pem -nodes
openssl pkcs12 -in legacyy_dev_auth.pfx -nokeys -out cert.pem
  • openssl pkcs12 — Use OpenSSL to work with PKCS#12 (.pfx / .p12) certificate bundles.
  • -in legacyy_dev_auth.pfx — Specifies the input file (the .pfx bundle containing cert + private key).
  • -nocerts — Extract *only the private key*, not the certificate.
  • -out key.pem — The extracted private key will be saved as key.pem.
  • -nodes — Do **not** encrypt the private key (keeps it in plaintext). Without this, OpenSSL would ask for a password to encrypt it.
  • -nokeys — Extract *only the certificate(s)*, not the private key.
  • -out cert.pem — The extracted certificate will be saved as cert.pem.

Basics

Check OpenSSL version

kali@kali:~ $ openssl version -a

Inspect a private key / certificate

kali@kali:~ $ openssl rsa -in key.pem -check -noout          # RSA private key
kali@kali:~ $ openssl x509 -in cert.pem -text -noout         # certificate details
kali@kali:~ $ openssl pkey -in any_key.pem -text -noout      # modern (any key type)

Keys & CSRs

Generate a private key (modern)

kali@kali:~ $ openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out server.key
kali@kali:~ $ chmod 600 server.key

Create a CSR

kali@kali:~ $ openssl req -new -key server.key -out server.csr
# Answer prompts (CN=hostname). Use -subj for non-interactive:
kali@kali:~ $ openssl req -new -key server.key -out server.csr \
  -subj "/C=US/ST=FL/O=valentine/CN=valentine.htb"

Self-signed cert (testing)

kali@kali:~ $ openssl req -x509 -new -nodes -days 365 \
  -key server.key -out server.crt -subj "/CN=localhost"

Formats & Conversion

PEM ↔ DER

# Cert: PEM → DER
kali@kali:~ $ openssl x509 -in cert.pem -outform DER -out cert.der
# Key: PEM → PKCS#8 DER
kali@kali:~ $ openssl pkey -in key.pem -outform DER -out key.der

PKCS#12 (.p12/.pfx) bundle

# Make P12 from key + cert (+ chain)
kali@kali:~ $ openssl pkcs12 -export -inkey key.pem -in cert.pem -certfile chain.pem -out bundle.p12
# Extract key/cert from P12
kali@kali:~ $ openssl pkcs12 -in bundle.p12 -nocerts -out key.pem
kali@kali:~ $ openssl pkcs12 -in bundle.p12 -nokeys  -out cert.pem

Real Case: Decrypting an Encrypted RSA Key

If a PEM has headers like Proc-Type: 4,ENCRYPTED and DEK-Info: ..., it is passphrase-protected. Decrypt to a plaintext key (for use with SSH or services). 

-----BEGIN RSA PRIVATE KEY-----
Proc-Type: 4,ENCRYPTED
DEK-Info: AES-128-CBC,AEB88C140F69BF2074788DE24AE48D46

DbPrO78kegNuk1DAqlAN5jbjXv0PPsog3jdbMFS8iE9p3UOL0lF0xf7PzmrkDa8R

kali@kali:~ $ openssl rsa -in hype_key -out hype_key_rsa
Enter pass phrase for hype_key: heartbleedbelievethehype
writing RSA key
kali@kali:~ $ chmod 600 hype_key_rsa
# Modern equivalent:
kali@kali:~ $ openssl pkey -in hype_key -out hype_key_rsa

Use decrypted key with SSH

kali@kali:~ $ ssh-keygen -y -f hype_key_rsa > hype_key_rsa.pub
kali@kali:~ $ ssh -i hype_key_rsa hype@<target_ip>

TLS Debugging

Connect and print certificate chain

kali@kali:~ $ openssl s_client -connect valentine.htb:443 -servername valentine.htb -showcerts
# Quit with Ctrl+C or send "Q" + Enter in some builds

Check a certificate file

kali@kali:~ $ openssl x509 -in server.crt -noout -dates -subject -issuer -fingerprint

Quick Crypto Utilities

Hash a file

kali@kali:~ $ openssl dgst -sha256 file.bin

Symmetric encrypt/decrypt (test data)

kali@kali:~ $ openssl enc -aes-256-cbc -pbkdf2 -salt -in secret.txt -out secret.enc
kali@kali:~ $ openssl enc -d -aes-256-cbc -pbkdf2 -in secret.enc -out secret.txt

Troubleshooting

  • “bad decrypt”: wrong passphrase or wrong key type/format.
  • “Expecting: ANY PRIVATE KEY”: you fed a certificate to a key command—use openssl x509 or the correct file.
  • “unable to load certificate / no start line”: PEM headers missing; ensure it begins with -----BEGIN …-----.
  • Permissions: many tools require chmod 600 key.pem.
  • OpenSSL 3.x: prefer openssl pkey/genpkey over legacy rsa/genrsa where possible.

Security Notes

  • Protect private keys (file mode 600, limit access, consider passphrases).
  • Remove passphrases only when a service can’t prompt and you control the host.
  • Never move real keys over insecure channels; use test/self-signed keys in labs.
