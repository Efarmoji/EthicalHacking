What is Gobuster?

gobuster is a fast, Go-based brute-forcing tool for discovering hidden web directories/files, DNS subdomains, virtual hosts, cloud buckets (S3/GCS), TFTP files and general fuzzing. It's lightweight, scriptable, and excellent for quick reconnaissance during CTFs or pentests.

Quick Start

Install

# Recommended (requires Go >= 1.20+):
go install github.com/OJ/gobuster/v3@latest

# Or use prebuilt binaries (GitHub releases) or container:
# ghcr.io/oj/gobuster:latest

# On Debian/Ubuntu/Kali (may be older version):
sudo apt update && sudo apt install gobuster
  • go install gives the latest v3.x when you have Go toolchain installed.
  • Binary/Docker is handy on machines without Go; releases are on the project's GitHub.

Basic usage pattern

gobuster <mode> [flags] — main modes: dir, dns, vhost, s3, gcs, fuzz, tftp.

Modes (short)

  • dir — directory / file brute forcing (wordlists against a webroot).
  • dns — subdomain discovery using a wordlist + DNS resolver.
  • vhost — virtual host discovery via Host header variations.
  • s3 / gcs — enumerate bucket names and check access.
  • fuzz — arbitrary HTTP fuzzing with custom payload placement.
  • tftp — brute-force files on a TFTP server.

Common flags & examples

Directory brute force (dir)

# Simple directory enumeration
gobuster dir -u https://example.com -w /usr/share/wordlists/dirb/common.txt

# Show status codes & response length
gobuster dir -u https://example.com -w wordlist.txt -s 200,204,301,302,401,403 -o gobuster-out.txt

# Use custom User-Agent and 50 concurrent threads
gobuster dir -u http://10.10.10.10 -w small.txt -t 50 -a 'Mozilla/5.0 (pentest)'

DNS (subdomain) enumeration

# DNS bruteforce using system resolver (or -r)
gobuster dns -d example.com -w subdomains.txt -t 40

# Using a specific resolver and showing CNAME records
gobuster dns -d example.com -w subdomains.txt -r 8.8.8.8:53 -o dns.txt

VHost detection

gobuster vhost -u http://10.10.10.10 -w vhosts.txt -t 30

Fuzz (custom)

# fuzzing with a token marker FUZZ; useful to try payloads inside path
gobuster fuzz -u 'http://example.com/FUZZ' -w fuzzlist.txt -t 60

# fuzz with custom headers and follow redirects
gobuster fuzz -u 'http://host/FUZZ' -w payloads.txt -H 'X-Api-Version: 2' -r

Flags cheat sheet

Flag Meaning Example
-u <URL> Target URL (for dir, vhost, fuzz). gobuster dir -u https://site.test -w wordlist.txt
-w <wordlist> Wordlist file path (required for most modes). -w /usr/share/wordlists/raft-small-words.txt
-d <domain> Domain to enumerate (for dns mode). gobuster dns -d example.com -w subs.txt
-t <threads> Number of concurrent threads (higher → faster but more load). -t 50
-s <codes> Show only responses with status codes (comma-separated). -s 200,301,302,403
-a <agent> Set custom User-Agent header. -a 'Mozilla/5.0 (pentest)'
-H <header> Add custom header (can be used multiple times). -H 'Authorization: Bearer TOKEN'
-r Follow redirects. -r
-x <extensions> Append file extensions (comma-separated) while bruteforcing (e.g., php,html). -x php,html,txt
-o <file> Write matched results to file. -o gobuster-results.txt
-k Skip TLS certificate verification (insecure; useful for self-signed lab targets). -k
-q Quiet mode — suppress banner and progress messages. -q
-e Show full URLs (including extensions and directories). -e
--wildcard Treat wildcard responses as valid (useful if server returns 200 for unknown paths). --wildcard

Practical examples & techniques

1) Fast recursion with extensions

gobuster dir -u http://10.10.10.10 -w /usr/share/wordlists/raft-large-directories.txt -x php,html,txt -t 75 -s 200,204,301,302,401,403 -o out.txt
  • Use a split: start with a small/fast wordlist to find endpoints, then re-run focused scans with larger lists.
  • Append extensions with -x for likely filetypes (php, aspx, jsp etc.).

2) Detect virtual hosts behind an IP

gobuster vhost -u http://10.10.10.10 -w vhosts.txt -t 30 -o vhosts.out
  • Check the responses for distinct status/length/body; some vhosts respond differently when Host header matches.

3) Subdomain discovery (with custom resolver)

gobuster dns -d example.com -w subdomains.txt -r 1.1.1.1:53 -t 40 -o dns-out.txt

Tips & common gotchas

  • Start conservative: high thread counts are fast but can trigger WAFs or break the target — adapt to the lab/target.
  • Wildcard behavior: if target returns 200 for unknown paths, use --wildcard to detect and filter false positives or supply a known non-existent path to compare.
  • Filter by size/status: combine -s with length-based heuristics to reduce noise (e.g., 200 but tiny length is often not useful).
  • Chaining: pipe gobuster results into other tools or scripts for automated verification; gobuster's -o makes integration easy.
  • Use smart wordlists: prefer targeted lists (e.g., app-specific endpoints) over huge generic lists when you have context.
  • Compare with ffuf/dirsearch: gobuster is fast and simple; ffuf offers richer fuzzing features (multiple markers, POST fuzzing) — use both when needed.

Quick troubleshooting

  • If nothing is found: check for a CDN/WAF, wildcard 200 responses, or that you are using the correct Host header / protocol (http vs https).
  • Use -k if testing self-signed HTTPS lab targets.
  • For noisy targets, reduce -t, add delays in your tooling, or run scans from a less aggressive network.

Output parsing example (one-liner)

# Show only URLs that return 200
grep 'Status: 200' gobuster-out.txt | awk '{print $NF}'
