What is git?

Git is a distributed version control system (VCS).
It tracks changes in files (especially code), letting you record, restore, and inspect past states over time.

  • Think of it like a time machine for your project folder
  • Every change is a "snapshot" (called a commit)
  • Supports team collaboration and rollback of any change

Core Components You Must Know

Term Meaning
Repository The Git-managed project directory (contains the .git folder)
Commit A saved snapshot of the file state at a specific point in time
Staging area (index) A preparation zone before committing
.git/ folder The hidden folder that stores everything Git knows (config, commits)

The Git Flow

Work → Stage → Commit → Log History

  • You modify files (work)
  • git add puts them in the staging area
  • git commit creates a snapshot
  • git log shows the commit history

✅ Key Git Commands (with security context)

Command Description Why it's useful
git init Initializes a new repo (.git/ is created) Start tracking changes
git status Shows modified/staged files See what's changed
git add <file> Stages file(s) for commit Prepares snapshot
git commit -m "msg" Saves staged changes Record changes
git diff Shows unstaged differences Spot inserted malware
git log Shows history of commits View past changes
git restore Unstages or resets files Undo mistakes
git checkout <hash> <file> Restore a file from a past commit For forensic comparison
git show <hash> Show full commit diff Audit the code precisely

🧠 From a Hacker's POV: Why Git is Powerful

When .git/ is leaked via web:

  • git log shows commit messages, authors, and timestamps
  • git diff reveals deleted code (often containing secrets, backdoors, API keys)
  • git checkout file.php lets you restore deleted/modified versions
  • git restore --staged . is great to unstage files, then use git diff to see their content

This is a treasure trove for attackers.

Why People run git status before log

  • git status tells you “where you are and what's changed now
  • Branch & state check: Confirms current branch, detached HEAD, or if a merge/rebase/cherry-pick is in progress.
  • Clean vs dirty tree: Shows unstaged/unstashed changes and untracked files. If the tree isn't clean, the latest commit in log may not reflect what will be committed.
  • Next action decision: Decides whether to stash, stage, or commit before digging into history (which avoids mixing investigative changes with real work).

Explanation for git log

  • Shows commit history: git log displays a chronological list of commits, starting from the most recent. Each entry includes a unique commit hash, author name, date, and commit message.
  • Commit hash: The long hexadecimal string (e.g., d387abf...) uniquely identifies a snapshot of the project at a given point in time. You can use this hash to checkout, revert, or cherry-pick that specific commit.
  • Author & Date: Useful for tracking who made a change and when it was made — important in team collaboration and auditing.
  • Commit message: A human-readable summary of the change. Good messages improve project maintainability by explaining the intent behind the code.
  • Default format: Without any flags, git log gives the full commit details. You can customize it using options like --oneline, --graph, or --stat for a more compact or visual history.

Explanation for git diff 1422e5a0... d387abf6...

  • What it does: Compares two commits and shows the changes between them. Here, it compares commit 1422e5a0... (older) to d387abf6... (newer).
  • Argument order matters: git diff A B shows changes needed to go from A → B. Deletions in B (relative to A) appear as removed lines/files.
  • Per-file header: The line diff --git a/... b/... marks the start of a file's diff block.
  • File mode line: deleted file mode 100644 means the file existed in A and was deleted by B (permissions were 0644).
  • Index line: index 44c981f..0000000 shows blob hashes before and after. 0000000 indicates “no file” (deleted).
  • --- / +++ headers: --- is the old path (A), +++ is the new path (B). Deleted files typically show +++ /dev/null (sometimes truncated in samples).
  • Hunks: Each change region starts with @@ ... @@ and then the minus (-) lines show removals, plus (+) lines show additions.
  • Narrow to a path (optional): You can add a pathspec to see just one file: git diff 1422e5a0 d387abf6 -- resources/integration/authcredentials.key.
  • Reverse the view: Swap arguments to see the inverse change: git diff d387abf6 1422e5a0 (deletions become additions, etc.).
  • Useful flags: --name-only (just filenames), --stat (summary), --word-diff (inline changes), --color (force colors).
  • Other comparisons: Omit the second commit to compare a commit vs working tree: git diff d387abf6. Use --staged to compare index vs HEAD.

Explanation for git checkout d387abf -- resources/integration/authcredentials.key

  • Purpose: Restores resources/integration/authcredentials.key to the exact version from commit d387abf in your working tree and index (staging area). Your current branch/HEAD does not move.
  • -- separator: Tells Git that everything after it is a pathspec (file paths), avoiding ambiguity between commit names and filenames.
  • Overwrites local changes (to that file): Any uncommitted edits to this path will be replaced. If you need to keep them, back up first or use a patch-based restore.
  • Next step: After restoring, make a commit to record the reversion:
    git commit -m "Restore authcredentials.key from d387abf"
  • Preview before restoring: Inspect the file content at that commit:
    git show d387abf:resources/integration/authcredentials.key
  • Modern equivalent (preferred):
    git restore --source d387abf -- resources/integration/authcredentials.key
  • Compare with reverting a commit: git checkout <commit> -- <path> restores a file from a past snapshot. git revert <commit> creates a new commit that inverses the entire commit’s changes across all files.
  • Narrowing scope: You can specify multiple files or directories after --, e.g.:
    git checkout d387abf -- path/one path/two

Useful git diff Flags

Flag What it shows / does Example
--name-only List only changed file names. git diff A B --name-only
--name-status List file names with status letters (A,M,D,R…). git diff A B --name-status
--stat Per-file summary of insertions/deletions. git diff A B --stat
--word-diff Inline word-level changes instead of whole lines. git diff A B --word-diff
-w / --ignore-all-space Ignore all whitespace when comparing. git diff A B -w
--ignore-space-change Ignore whitespace changes (but not additions/deletions of lines). git diff A B --ignore-space-change
--unified=<n> Show <n> context lines around changes (default 3). git diff A B --unified=1
--diff-filter=<set> Limit to certain change types (e.g., D for deletes, M for modifies). git diff A B --diff-filter=D
--find-renames Detect file renames and show them as such. git diff A B --find-renames
--find-copies Detect file copies. git diff A B --find-copies
--binary Include binary diffs (useful in patches). git diff A B --binary
--relative Show changes only under the current directory. git diff A B --relative
--color Force colorized output (helpful in some terminals). git diff A B --color
-- <path> Limit diff to specific path(s) (pathspec separator). git diff A B -- resources/integration/authcredentials.key
