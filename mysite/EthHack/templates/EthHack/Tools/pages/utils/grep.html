What is grep?

grep searches files and streams for lines matching a pattern (plain text or regex). It’s essential for log triage, code review, secret hunting, and chaining with other tools.

Usage

Extract word -> wordlist creation

grep -oP '(?i)(?<=supportdesk\\)[^:\s\)\\]+'
    
  grep -oP
  '(?i)                   ← ignore uppercase/lowercase
   (?<=supportdesk\\)     ← start matching right after “supportdesk\”
   [^:\s\)\\]+'            ← extract characters until :, whitespace, ), or \ appears'

Grep only ports

grep '/tcp' ports | cut -d'/' -f1 | paste -sd, -
22/tcp open ssh
80/tcp open http
443/tcp open https
53/udp open domain

Quick Start

Basic finds

kali@kali:~ $ grep "ERROR" app.log                   # simple match
kali@kali:~ $ grep -n "ERROR" app.log                # show line numbers
kali@kali:~ $ grep -i "login failed" auth.log        # case-insensitive
  • grep "ERROR" app.log — print lines in app.log that contain the exact text ERROR.
  • grep -n "ERROR" app.log — same, plus a prefix with the line number of each match.
  • grep -i "login failed" auth.log — case-insensitive search (matches “Login Failed”, “LOGIN FAILED”, etc.).

Recursive project search

kali@kali:~ $ grep -R "api_key" .                                  # recurse current tree
kali@kali:~ $ grep -R --include="*.php" -n "mysqli" /var/www/html  # only *.php
kali@kali:~ $ grep -R --exclude-dir=".git" --exclude="*.min.js" token .
  • grep -R "api_key" . — search the current directory tree recursively for lines containing api_key.
  • grep -R --include="*.php" -n "mysqli" /var/www/html — scan only PHP files under the webroot; show line numbers where mysqli appears.
  • grep -R --exclude-dir=".git" --exclude="*.min.js" token . — skip the .git directory and minified JS while searching for token.

Regex power (extended / PCRE)

kali@kali:~ $ grep -E "(password|passwd|secret|api[_-]?key|token)" -R .  # extended regex
kali@kali:~ $ grep -Po "(?i)bearer\s+[a-z0-9\._\-]+" -R .                 # PCRE + only match (-o)
  • grep -E "(password|passwd|secret|api[_-]?key|token)" -R . — use extended regex to find any of the listed terms (handles api-key or api_key), recursively.
  • grep -Po "(?i)bearer\s+[a-z0-9._\-]+" -R . — PCRE mode; case-insensitive Bearer followed by a token; -o prints only the token itself.

Context & highlighting

kali@kali:~ $ grep --color=auto -n "Exception" -C2 server.log      # 2 lines around
kali@kali:~ $ grep -A3 -B1 "CRITICAL" service.log                  # after/before blocks
  • grep --color=auto -n "Exception" -C2 server.log — highlight matches; show 2 lines of context before and after each match with line numbers.
  • grep -A3 -B1 "CRITICAL" service.log — show 1 line before (-B1) and 3 lines after (-A3) every “CRITICAL” hit.

Useful Flags

Flag What it does Example
-R/-r Recursive search ( -R follows symlinks ) grep -R "jwt" .
-i Ignore case grep -i "admin"
-n, -H, -h Show line numbers / force filename / hide filename grep -nH "pattern" file
-E, -P, -F Extended regex / PCRE / fixed string (no regex) grep -F "a+b*c" file
-w Match whole word grep -w "root" /etc/passwd
-v Invert match (show non-matching lines) grep -v "^#" config
-o Print only the matching part grep -Eo "[0-9a-f]{32}" file
-A/-B/-C After / Before / Context lines grep -C3 "ERROR" log
--include/--exclude Filter files by glob grep -R --include="*.py" todo .
--exclude-dir Skip directories grep -R --exclude-dir=".git" pass .
--color=auto Highlight matches grep --color=auto -n secret file
-l/-L List files with/without matches grep -Rl "DEBUG" .
-Z + xargs -0 Null-separated filenames (safe with spaces) grep -RlZ "pattern" . | xargs -0 sed -n '1p'
-a/-I Treat binary as text / ignore binary grep -a -R "JWT" dump.bin
-m N Stop after N matches per file grep -m 1 "secret" *
-s Silent errors (useful in scripts) grep -s "root" /proc/*/status

Examples in Context

Secret / credential hunting

kali@kali:~ $ grep -RinE "(password|passwd|secret|api[_-]?key|token)" --exclude-dir=".git" .
kali@kali:~ $ grep -RinE "(AKIA[0-9A-Z]{16})" .                      # AWS Access Key ID
kali@kali:~ $ grep -RinE "Bearer\s+[A-Za-z0-9\._\-]+" .
  • grep -RinE "(password|passwd|secret|api[_-]?key|token)" --exclude-dir=".git" . — recursively search with line numbers and case-insensitive extended regex for common secret keywords, skipping the .git directory.
  • grep -RinE "(AKIA[0-9A-Z]{16})" . — look for AWS Access Key IDs across the tree (pattern: “AKIA” + 16 base-36 uppercase chars).
  • grep -RinE "Bearer\s+[A-Za-z0-9._\-]+" . — find Bearer tokens in source or logs; prints the line number and the lines containing tokens.

Webroots & logs

kali@kali:~ $ grep -R --include="*.{php,js,conf}" -n "mysqli|pdo" /var/www/html
kali@kali:~ $ grep -R --exclude-dir="{node_modules,vendor}" -n "TODO|FIXME" .
kali@kali:~ $ grep --color=auto -nC2 " 500 " /var/log/nginx/access.log
  • grep -R --include="*.{php,js,conf}" -n "mysqli|pdo" /var/www/html — focus on likely code/config files to flag DB usage (mysqli or PDO) with line numbers.
  • grep -R --exclude-dir="{node_modules,vendor}" -n "TODO|FIXME" . — find unfinished code markers while skipping heavy third-party trees.
  • grep --color=auto -nC2 " 500 " /var/log/nginx/access.log — highlight HTTP 500s with two lines of context for quick incident review.

Exact words & performance

kali@kali:~ $ LC_ALL=C grep -R --binary-files=without-match -n -w "root" /etc  # faster ASCII path
kali@kali:~ $ grep -RF "a+b*c" .                                              # -F: treat as literal
  • LC_ALL=C grep -R --binary-files=without-match -n -w "root" /etc — set a fast C locale; recurse; skip binary files; show line numbers; match the whole word “root”.
  • grep -RF "a+b*c" . — recursive, fixed-string search (ignores regex metacharacters) for the literal text a+b*c.

Tips

  • Quote your patterns to prevent shell expansion (use single quotes for regex).
  • -F is faster when you don’t need regex (treats pattern literally).
  • Use --include/--exclude/--exclude-dir to keep searches tight and fast.
  • Need richer features/speed on huge repos? Try ripgrep (rg) as a complement.

Explain: grep -Pv "^( |Image)"

kali@kali:~ $ identify -verbose 68e1fb69a0a44.png | grep -Pv "^( |Image)"
  • -P: Use PCRE (Perl-compatible) regex engine. (Not strictly needed here, but allows advanced patterns.)
  • -v: Invert the match — show lines that do not match the pattern.
  • Pattern ^( |Image):
    • ^ = start of line.
    • ( |Image) = either a single leading space or the literal word Image.
    So the command filters out lines that begin with a space or begin with Image, leaving lines that are flush-left and not the header — e.g., the raw hex block.

Why this works on identify -verbose output

  • Image: is a top-level header printed at column 1.
  • Most metadata lines are indented (start with a space).
  • The embedded hex data lines are flush-left (no leading spaces), so they survive the filter.

Variants you may prefer

# Keep only pure hex lines (safer / more explicit)
kali@kali:~ $ identify -verbose 68e1.png | grep -E '^[0-9A-Fa-f]+$'

# Extract just the hex between "Raw profile type:" and "signature:", decode to a file
kali@kali:~ $ identify -verbose 68e1.png \
  | awk '/Raw profile type:/,/^  signature:/' \
  | grep -E '^[0-9A-Fa-f]+$' \
  | tr -d '\n' \
  | xxd -r -p > extracted.bin

# Using POSIX ERE instead of PCRE (works for this simple pattern)
kali@kali:~ $ identify -verbose 68e1.png | grep -vE '^( |Image)'

Tip: If any non-hex, flush-left lines appear (e.g., a lone length like 1437), the explicit hex-only pattern ^[0-9A-Fa-f]+$ is the most reliable filter.
