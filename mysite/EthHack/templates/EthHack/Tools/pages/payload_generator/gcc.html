Compile command explained

Command

i686-w64-mingw32-gcc xxxx.c -o xxxxx.exe
gcc -pthread exploit.c -o exploit -lcrypt

What each part means

  • gcc — the GNU C Compiler. It compiles and links C source files into executables.
  • -pthread
    • Enables POSIX threads support.
    • Does two things: (1) defines the right macros when compiling (so thread-aware headers behave correctly), and (2) tells the linker to link with the pthread library (libpthread).
    • Use this when your program uses pthread_create, mutexes, condition variables, etc.
  • exploit.c — the C source file you want to compile.
  • -o exploit
    • Sets the output filename to exploit (instead of the default a.out).
  • -lcrypt
    • Link with the libcrypt library (functions like crypt() used for password hashing).
    • Putting -lcrypt after the source/object files is important because the linker resolves symbols left → right.

How it runs (step-by-step)

  • Preprocessing & compiling: exploit.c is converted to object code (machine code).
  • Linking: object code is linked with required libraries (libpthread, libcrypt, libc, ...) to produce a single executable named exploit.
  • Result: a runnable binary ./exploit.

Common pitfalls & tips

  • Order matters: libraries (flags like -lcrypt) should come after source/object files so the linker can resolve undefined symbols.
  • Prefer -pthread over manually adding -lpthread: -pthread ensures correct compile-time macros as well as linking.
  • If you get “undefined reference” errors: make sure the corresponding -l option appears after the object or source files that need it.
  • Static vs dynamic libs: -lcrypt links the system crypt library (usually dynamic). If you need a static binary, pass -static (but that has further implications).
  • Check runtime dependencies: use ldd ./exploit to see which shared libraries the produced binary needs.

Example: compile, inspect, run

  • gcc -pthread exploit.c -o exploit -lcrypt
ls -l exploit
ldd ./exploit
./exploit

Minimal secure suggestion

  • If you only need threading and no crypt(), omit -lcrypt. Only link libraries you actually use.
  • When building complex projects, prefer a Makefile to keep compile flags consistent.
