Impacket-psexec

Lightweight Python implementation of PsExec-style remote execution using SMB — uploads a temporary service binary and executes it to run commands on a Windows host. Requires valid credentials (username/password or NTLM hash) or an elevated context. Only use on systems you own or are explicitly authorized to test.

Quick summary

Runs commands or a remote shell by creating a service on the target via SMB RPC, copying an executable, and starting it. Common in red-team engagements and labs for post-auth remote command execution.

Copy-ready examples

impacket-psexec Administrator:'Passw0rd'@10.10.10.5 cmd.exe
impacket-psexec -hashes aad3b435b51404eeaad3b435b51404ee:e0fb1fb85756c24235ff238cbe81fe00 administrator@10.129.228.112 cmd.exe
impacket-psexec -no-pass 10.10.10.5 'DOMAIN\\svc_account'@10.10.10.5 cmd.exe

Common options (short)

OptionMeaning (one line)
-u USERUsername to authenticate as.
-p PASSPassword (plain) or -no-pass to use empty password.
-hashes LM:NTHUse NT/LM hashes instead of plaintext password.
-kUse Kerberos for auth (with valid ticket).
-debugShow verbose debugging network output.

How it works (short)

  • Connects to target SMB and creates a temporary service binary in \\ADMIN$\\ (\Windows\Temp or similar).
  • Creates and starts a Windows service pointing to that binary (via RPC), which runs the requested command.
  • After execution it attempts to remove the service and cleanup the uploaded file.

Notes & safety

  • Requires valid credentials with rights to write to ADMIN$ and create services (often administrative).
  • Antivirus/EDR may block the uploaded binary or detect the behavior; use in controlled labs only.
  • Prefer authenticated and permitted testing — never against production systems without authorization.
