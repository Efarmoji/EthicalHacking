What is certipy-ad?

Offensive tool for enumerating and abusing Active Directory Certificate Services (AD CS).

Subcomand

Name Role
find Automated enumeration and vulnerablity analysis
template Display details of certain template
req Get certification using arbitrary template.
auth Use .pfx file to get hash, TCP/TGS with PKINIT authentication
shadow Control Shadow Credential
account Manage user and machine accounts

Usage

find

certipy-ad find -u 'PRIVILEGE_USER' -hashes HASH -dc-ip $IP -vulnerable -stdout
  • -dc-ip IP → contact this IP as the domain controller / KDC / LDAP/DC endpoint.
  • -vulnerable → perform extra checks to identify “vulnerable” certificate templates / misconfigurations (templates whose ACLs/policies allow low-privilege enrollment, arbitrary SAN/subject specification, or otherwise can be abused).
  • -stdout → output details without saving file.

template

certipy-ad  template -u PRIVILEGE_USER -hashes HASH -dc-ip $IP -template TEMPLATE_NAME -target DOMAIN_MACHINE_NAME -save-old
  • -u PRIVILEGE_USER — Domain user used to read template/CA settings (regular user is usually enough).
  • -hashes HASH — NTLM hash (format: LM:NT or :NT). Use instead of a password.
  • -dc-ip $IP — Direct DC IP for LDAP/Kerberos queries to avoid flaky name resolution.
  • -template TEMPLATE_NAME — Exact template name to inspect (e.g., User, Machine, DunderMifflinAuthentication).
  • -target DOMAIN_MACHINE_NAME — Optional. Hostname/FQDN used for RPC/LDAP context; helpful with multiple DCs or unstable DNS.
  • -save-old — If any change occurs (rare for template reads), keep the previous value. Safe to include as a precaution.
  • What it shows — EKUs, enroll/auto-enroll ACLs, subject/SAN supply method (Supply in request / Build from AD), SAN requirements (UPN/DNS/SID), expected privileges, and ESC hints.
  • Tips — If output looks incomplete, add -debug. For unstable SMB/RPC in other subcommands, use -rpc tcp (pure LDAP reads don't need it).

req

certipy-ad req -ca CERTIFICATE_AUTHORITY -u PRIVILEGE_USER -hashes HASH -dc-ip $IP -template TEMPLATE_NAME -target DOMAIN_MACHINE_NAME -upn administrator@DOMAIN -debug
  • -ca CERTIFICATE_AUTHORITY — CA display/internal name to submit the request to (e.g., sequel-DC01-CA).
  • -u PRIVILEGE_USER / -hashes HASH — Account and NTLM hash used to authenticate to AD/CA (use LM:NT or :NT).
  • -dc-ip $IP — Domain Controller IP for LDAP/Kerberos (stabilizes lookups).
  • -template TEMPLATE_NAME — Certificate template to use (must be supported by the CA and allow your principal to enroll).
  • -target DOMAIN_MACHINE_NAME — Optional. Host/FQDN used for RPC/LDAP context in mixed/unstable environments.
  • -upn administrator@DOMAIN — Request a cert bound to this UPN in SAN/subject (requires a template/CA that allows “Supply in request”).
  • -dns HOST.DOMAIN — Add a DNS SAN entry (again requires enrollee-supplied SAN to be permitted).
  • -sid S-1-5-21-… — Add an object SID to SAN (used by some attacks; needs template support).
  • -subject "CN=Name" — Set the subject when the template allows client-supplied subject.
  • -machine — Treat the requester as a machine account (use with computer creds or after adding a computer).
  • -rpc tcp — Use RPC over TCP instead of SMB named pipe (more stable over flaky links/VPNs).
  • -timeout 60 — Increase RPC request timeout (useful on high-latency links).
  • -debug — Verbose diagnostics (often “slows down” just enough to avoid transient RPC timing issues).

auth

certipy-ad auth -pfx administrator.pfx
  • -pfx administrator.pfx — Use the issued PFX to perform PKINIT and authenticate as that identity.
  • -dc-ip $IP — Domain Controller to talk to for Kerberos (recommended to avoid DNS flakiness).
  • -domain DOMAIN — Kerberos realm/AD domain; usually inferred from the cert, but you can override it.
  • -username USER — Override the principal if needed (rare; typically derived from the cert’s UPN/SAN).
  • -no-pass — If the PFX has no password (or use -pfx-password to supply one).
  • -ptt — Inject the obtained TGT/TGS into the current session (Pass-the-Ticket) right away.
  • -impersonate TARGET — If supported/valid (e.g., with constrained delegation chains), request a service ticket for another user.
  • -save-ccache OUT.ccache — Save tickets to a ccache file for later use with other tools.
  • -debug — Verbose output (helpful to confirm PKINIT succeeded and see ticket details).

shadow auto

certipy-ad shadow auto -u USER@DOMAIN -p PASS -account 'TARGET_USER' -dc-ip $IP
