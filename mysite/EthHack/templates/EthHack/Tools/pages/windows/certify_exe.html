What is certify.exe?

Certify.exe is a tool (part of the GhostPack/Certify family) for enumerating and interacting with Active Directory Certificate Services (AD CS). It lets an operator discover CAs and templates, test template permissions/weaknesses, and submit certificate requests.

What is ADCS?

AD CS is an acronym for Active Directory Certificate Services, a Microsoft role in Windows Server that manages public key infrastructure (PKI) and digital certificates. It allows organizations to issue and manage digital certificates used for encrypting communications, authenticating users and devices, and creating digital signatures, ensuring data integrity and confidentiality within a network.

Like Kerberos, you can use this to intercomunicate OUs.

Usage

Enumerates reachable CA

.\Certify.exe cas
  • What it does (high level): enumerates reachable Certificate Authorities in the domain and prints basic information about them (CA hostnames, service names, supported protocols/ports, maybe their CA types and templates).
  • Why useful: finding which machines run AD CS and which CA objects exist is the first step for assessing AD CS attack surface.
  • Output you'll see: list of CA objects / endpoints and metadata about each CA.

Identify templates that are misconfigured or have weak ACLs

.\Certify.exe find /vulnerable
  • What it does (high level): scans CA(s) and their certificate templates to identify templates that are misconfigured or have weak ACLs — i.e., templates that allow low-privilege users to enroll or to supply arbitrary subject/SANs. It flags templates that could be abused to obtain certificates for other identities.
  • Why useful: identifies vulnerable templates that, if abused, may allow elevation (for example, issuing a cert that represents another user/machine or a high-privilege account).
  • Output you'll see: a list of templates and a vulnerability status/notes (which template permissions allow which actions).

Request a certificate

.\Certify.exe request /ca:dc.sequel.htb\sequel-DC-CA /template:UserAuthentication /altname:administrator
  • What it does (high level): attempts to request a certificate from the specified CA (dc.sequel.htb\sequel-DC-CA) using the named template (UserAuthentication) and requests that the certificate include an alternative name (altname:administrator). In other words, it submits a certificate enrollment request that asks the CA to issue a cert for the given alt-name/subject.
  • Important nuance / prerequisites:
  • Whether the CA issues the certificate depends on the template ACLs and CA policy. The requesting account must have whatever enrollment rights the template requires.
  • Some templates allow the requester to supply the subject or SAN (or allow enrollments by low-privilege users) — if so, an attacker could request a cert that appears to represent another identity.
  • Possible outcomes: request is denied (insufficient rights), request is pending (requires manual approval by CA admins), or CA issues a certificate (meaning the template/CA policy allowed it).
