What is john?

john (John the Ripper) is a widely used password-cracking tool. It supports many hash formats (Unix passwd, /etc/shadow, MD5, NTLM, bcrypt, ZIP/RAR/PBKDF2 containers, etc.) and multiple attack modes (wordlist, incremental/brute force, rules). Use it to test password strength and recover forgotten credentials — only on systems you own or are explicitly authorized to test.

Quick Start

Basic usage

# crack a simple hash file with a wordlist
john --wordlist=/usr/share/wordlists/rockyou.txt hashes.txt

# show cracked passwords
john --show hashes.txt

# auto-detect format and run incremental (slow but thorough)
john --incremental hashes.txt

# use a specific format (e.g., raw-md5)
john --format=raw-md5 --wordlist=rockyou.txt hashes.txt
  • john <file>: default run (tries autodetected modes/formats).
  • --wordlist=FILE (or -w:FILE): use a wordlist / dictionary.
  • --rules (or -r): apply rules (mutations) to wordlist entries.
  • --incremental: brute-force / incremental mode (very powerful, slow).
  • --format=NAME: force hash format when auto-detection fails (useful for ambiguous hashes).
  • --show: display cracked entries and their plaintexts from a session.

Common Flags & Options

Flag What it does Example
--wordlist=FILE Use FILE as dictionary input (faster than brute force) --wordlist=/usr/share/wordlists/rockyou.txt
--rules / -r Apply rule set to mutate dictionary words (e.g., add numbers, case variants) --wordlist=rockyou.txt --rules
--incremental Incremental (brute-force) mode using tuned character sets --incremental=All
--format=NAME Force a specific hash format (if autodetect fails) --format=nt --wordlist=rockyou.txt nt_hashes.txt
--show Show cracked passwords and remaining hashes john --show hashes.txt
--session=NAME Save / resume sessions (useful for long cracking jobs) --session=weekend_crack --wordlist=rockyou.txt hashes.txt
--pot=FILE Specify potfile (where cracked results are stored) --pot=/tmp/john.pot
--stdout Dump wordlist (with rules) to stdout (useful for piping into other tools) john --wordlist=rockyou.txt --rules --stdout | head

Preparing input files

  • Unix /etc/shadow: use the whole shadow or extract a specific user. For passwd+shadow pairs, use unshadow to merge into a john-readable file: 
    unshadow /etc/passwd /etc/shadow > unshadowed.txt
john unshadowed.txt
  • Windows / NTLM: if you have NTLM hashes, place them in a file (one per line) and use --format=NT or let john auto-detect.
  • Archive containers (ZIP/RAR/7z): use helper tools to extract hash blobs: 
    zip2john secret.zip > zip.hash
john --wordlist=rockyou.txt zip.hash

Examples

Wordlist + rules (fast, effective)

john --wordlist=/usr/share/wordlists/rockyou.txt --rules hashes.txt

Force format (NTLM example)

john --restore=bigjob

Code snippet

Line-by-line explanation (what each part does)

  • zip2john secret_archive.zip > secret.hash — extract the ZIP's password hash into a john-readable file.
  • john --wordlist=... secret.hash — run john using a wordlist to attempt to crack the ZIP password quickly.
  • john --show secret.hash — display cracked passwords (if any) from john's potfile.

john --wordlist=/usr/share/wordlists/rockyou.txt combined.txt

Formats & how to detect them

John supports many --format names (e.g., md5crypt, raw-md5, raw-sha1, LM, NT, bcrypt, pbkdf2-hmac-sha1). If john fails to crack or mis-detects, force the format. Use john --list=formats to see supported formats.

Advanced tips

  • Start with wordlist + rules: it's the fastest path to results for human passwords.
  • Use tuned rule sets (e.g., --rules=Jumbo or community rule files) — they multiply wordlist effectiveness without full brute force.
  • Use --stdout to pipe mutated wordlists into other tools or into hashcat if you prefer GPU cracking:
    • john --wordlist=rockyou.txt --rules --stdout | hashcat -m 1000 -a 0 hash.txt -
  • Prepare helper tools: unshadow, zip2john, rar2john, 7z2john, pdf2john — they convert container formats to john-readable hashes.
  • Keep your potfile secure — it contains plaintext passwords john has recovered (~/.john/john.pot by default).
  • Use --pot= or custom session names to separate test runs and avoid contaminating global potfile.
  • If a hash resists CPU cracking, consider GPU tools (hashcat) for faster throughput on supported formats.

Performance & practical workflow

  1. Collect hashes (unshadow / zip2john / etc.).
  2. Try targeted wordlists (company names, leaked corp lists, passphrases related to target) + rules.
  3. If unsuccessful, escalate to larger wordlists with stronger rules or hybrid attacks (prefix/suffix numbers).
  4. Use incremental/brute force as last resort (costly in time).
  5. Always resume long jobs with --session and monitor progress with john --status.

Safety & ethics

Cracking passwords can be legally and ethically sensitive. Only run john on hashes and systems you control or have explicit permission to test. Store cracked results securely and delete them when they are no longer needed.
