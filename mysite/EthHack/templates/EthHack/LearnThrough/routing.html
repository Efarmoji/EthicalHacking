🧠 Internet Routing & MITM Mechanism Summary

1. Internet Routing Mechanism: OSI Model <- Click here

Layer Protocols/Concepts Role in Routing
L1-2: Physical/Data Link Ethernet, Wi-Fi, ARP Deals with local MAC addresses; no internet-wide routing
L3: Network Layer IP (IPv4/IPv6), ICMP Core of routing: assigns IPs and forwards packets between networks
L4: Transport Layer TCP, UDP End-to-end communication; not responsible for routing itself
L7: Application Layer HTTP, DNS, SSL, etc. Where user actions (like visiting websites) take place

📡 2. IP Routing – The Core Mechanism <- click here

Every time a packet leaves a device, the IP layer decides where to send it next, based on the routing table.

🧭 How Routing Works

  • Local delivery?
    If destination IP is in the same subnet: use ARP to find MAC, deliver directly.
  • Different network?
    Forward to default gateway (router).
  • Router checks its routing table and sends the packet closer to its destination.
  • This process repeats until the packet reaches the destination.

📘 Example Routing Table (Linux)

$ ip route
default via 192.168.1.1 dev wlan0
192.168.1.0/24 dev wlan0 proto kernel scope link src 192.168.1.100

🕵️ 3. How MITM Exploits Routing

🔁 Scenario 1: ARP Spoofing (Local MITM)

  • You lie to the victim and router via fake ARP replies:
  • “Hey, I’m the router” (to victim)
  • “Hey, I’m the victim” (to router)
  • Both send their traffic to you, thinking you’re the other.

🌐 Scenario 2: Rogue Access Point

  • Devices connect to your fake Wi-Fi AP, thinking it's legit.
  • All traffic routes through you, and you forward it to the internet (via NAT).

🕸️ Scenario 3: DNS Spoofing

  • You intercept DNS requests (port 53).
  • Reply with a fake IP address for a domain.
  • Victim is routed to your server instead of the real one.
